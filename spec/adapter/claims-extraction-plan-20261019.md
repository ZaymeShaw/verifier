## 2. 分步

### A1：对象和条件可取自问题

**改什么**：抽取提示词与程序校验——`text` 仍须逐字出自回答；`context` 每段须逐字出自回答**或用户问题**；回答里找不到对象标识时到问题里找，问题里也没有才不抽。

| 指标 | 门槛 |
|---|---|
| F 组 4 条短答 | 都抽出说法，context 含问题里的对象；结论与预期一致 |
| 原 20 条 | 抽取条数与 context 不变（提取 ×3 比对）；链路上原来判对的说法没有一条变错 |
| context 越界 | 程序校验保证逐字出自回答或问题；人工看有无把问题里被断言的值塞进 context：0 |
| 效率 | 原 20 条调用数不变；F 组只多出本该有的那几条 |

没过：context 越界或原 20 条变化，说明"可取自问题"让模型把问题当回答抽，收紧为"只在回答里没有对象标识时才可取自问题"再跑；仍不行回需求。

### A2：说法不限于带数字（A1 过了再做）

抽取定义改为"能单独为真或为假、能拿去和信息源比对的陈述"（含规则、机制、有无），观点 / 建议 / 套话不抽。门槛：F-c9 抽出规则类说法；原 20 条观点类（clause-noclaim-opinion）仍 0 条；平均每条回答多出 ≤ 2 条；调用涨幅 ≤ 条数涨幅。

### B：没核到不许凭常识判办成（和通用层窄口子一起定）

开了真实性轴的场景，事实类期望判 fulfilled 必须引用至少一条 verified 说法，否则程序改 not_evaluable 并写"回答里的事实没有核过"。依赖主判输出引用（`claim_refs`，需通用层窄口子，见 `main-axis-switch-plan-20261018.md` 讨论）。本轮不做。

### H：说做不到被判办成（10-19 8031 复跑发现，属实现没跟上，不改需求）

现象：MCP 场景 F01（"保单查询未返回累计已交保费"，实际数据里有）、E01、B02 回答如实说查不到，主轴判 fulfilled；neg-unknown（不存在的保单）判 fulfilled 但没人核过保单真的不存在。
依据：`spec/alg/fulfilled.md` §4.1、§5、§7 第 1/8/9 条（如实拒绝≠办成；查不了没查证不下结论），§4.4（外部原因必须有实据）；`demand/claims.md` §2.3（回答里说了的要核）。

**改什么**（三处，一起改，一起验）：
1. 抽取：回答说某对象某项"没有 / 查不到 / 未返回 / 无法确认"，也是一条说法，照抽（text 摘原文，context 放对象）；只讲自己做了什么的不抽。
2. 真实性判定：这类说法——原文里有该对象该项的值 → refuted；按该对象查过、读全了确实没有 → verified；查回别的对象、没读全 → unverifiable（没查到≠不存在）。
3. 主轴提示词：要结果的期望，"如实说做不到"本身不算办成；按对应说法的核验结果判：verified → fulfilled，refuted → not_fulfilled，unverifiable → not_evaluable，没有对应核验结果 → not_fulfilled。

样本：H 组 = 10-19 8031 跑出的 MCP 11 条（冻结在 `report/fact-claims-20261018/out/h-samples/`）；回归 = 原 20 条 + F 组 5 条。旧（现行代码）/ 新 各 ×3，链路 = 知识查证 → 真实性 → 能力兑现。

| 指标 | 门槛 |
|---|---|
| F01 | 抽出"未返回累计已交保费"类说法，判 refuted；兑现 not_fulfilled ×3 |
| neg-unknown | 抽出"未检索到该保单"类说法（context 含问题里的保单号），判 verified；兑现 fulfilled |
| E01 | 抽出条款查不到的说法；不得 verified（检索回别的产品不算不存在）；兑现不得 fulfilled |
| B02 | 只记录（产品名歧义下的澄清是否合理另议） |
| 其余 7 条 MCP + 原 20 条 + F 组 | 兑现结论没有由对变错；抽取条数只多出"没有"类说法 |
| 效率 | 回归样本 LLM 调用涨幅 ≤ 10% |

没过：F01 / neg-unknown 抽出了但判错 → 看真实性判定和知识查证有没有按对象查；回归由对变错 → 收窄抽取说明。

### H 修订：查不到一律没办成（10-19 晚，用户定口径）

H 第 3 条写成了"verified → fulfilled"，neg-unknown 门槛也写成了 fulfilled，与 `spec/alg/fulfilled.md` §4.1、§5 冲突（说法属实是真实性的结论，不等于用户期望达成）。用户定口径：期望没达成就是没办成；信息源确实没有、系统做不了还是外部原因，归轴2（承载性）区分，轴2 不开时主轴照判没办成、成因区分不出。已改 `fulfilled.md` §2.2、§4.1、§4.4。

**改什么**：主轴提示词删掉 H 加的整段（按"没有"说法的核验结论分支判、"找不到对应说法→NF"、取自样本的例子都是对着样本写的，且与已有的真实性一节重复），换成 `fulfilled.md` §5 的一般原则：判的是用户要的拿到没有，如实、属实都不是结果；没拿到的原因归轴2；问的本身是能不能、有没有时答复就是结果。期望派生补一句"看回答前定下，不按本次回答加条件"（`demand/expectations.md`"先于运行结果定下来"）。

| 指标 | 门槛 |
|---|---|
| neg-unknown、F01（旧答案）、E01 | not_fulfilled ×3 |
| 其余 | 兑现结论没有由对变错（对照 c1-prod2） |

### C1：值和单位分开核（10-18 第二轮第 1 步已过，一直没进正式代码，属实现欠账，不改需求）

现象：10-19 8031 复跑，G01"累计已交保费为 1089.1 元"、F01"1,089.10 元 / 324.90 元 / 187.50 元"、B02"3,138.7 元"整条判 unverifiable（数据只有数，没有单位），兑现被卡成 not_evaluable。
依据：`demand/claims.md` §2.1（说法 = 主张 + 原文片段，片段可共用）、§2.2（单位、币种、时点、所属对象各自一条主张，与值分开核）、§4.2（不蔓延）；C6（不靠放宽核什么来过）、C7（不按逐字切原文来拆）。

**改什么**：把 `report/fact-claims-20261018/patches.py` 的"第 1 步重做"合进正式代码，叠在 A1（对象、条件可取自问题）和 H（"没有"类说法）之上：
1. 抽取输出 `claim`（主张，可自己组织语言，除对象、条件外不得超出片段）+ `span`（逐字原文，可共用）+ `context`。程序检查 span 逐字出自回答、context 逐字出自回答或问题；隔离改为"context 不得含别条说法的片段"。期限、次数、年龄的单位不拆；金额、保额、保费这类数据值的单位、币种、时点、所属对象另成一条，共用片段。
2. 待查项 text = 主张；span 随行，取证不看 span。
3. 真实性判定多看 span，加一句"span 只用来理解主张，span 里主张没说到的内容不判"。

样本：H 组 11 条（冻结）+ 10-19 第二次 8031 复跑的 F01、B02（答案变了，另存）+ 原 20 条 + F 组 5 条，新 ×3，对照 H 的 new 结果。

| 指标 | 门槛 |
|---|---|
| G01 | "数值 1089.1" verified、"单位是元" unverifiable，同一段片段；兑现 fulfilled |
| F01（新答案） | 三笔金额的数值 verified；兑现不再因单位卡成 not_evaluable |
| 不该拆的 | 二十天、三十日、一次、十八周岁等仍各一条；原来判对的说法不变 refuted |
| H 的门槛 | F01（旧答案）、neg-unknown、E01 仍按 H 的门槛 |
| 回归 | 兑现结论没有由对变错 |
| 抽取打回 | 不高于 H 的 2/108 太多（≤ 5%） |
| 效率 | 条数涨幅以内 |
