# 过程六轴：抽象先行的优化方案（2026-09-27）

依据：`~/Downloads/process-axes-v3.md`（六轴方向性定义）、Cursor 典范 `report/process-axes-adjudication-20260924/README.md`、
最新结果 `~/Downloads/verifier-llm_probe-cases-20260926-235109.xlsx` 的复核。

## 0. 要解决的问题

最新表暴露的不是某个轴的提示词写得不好，而是三件系统性的事：

1. **轴边界漂移**：同类情况在不同用例里落到不同轴（预算/准入拒绝记成工具故障；多余澄清记在意图轴；知识轴的"原因类型"混写；模型轴被格式违约淹没）。
2. **核心结论被程序处理弄没**：已被证据证明的 fail，因引用不在视图内被降为缺证（E01 上下文轴）；约一半缺证项来自程序降级而非模型判断；降级原因不导出，人看不到。
3. **前置分析轴是单点且脆弱**：本批 B10/B17/C09/F20 的整理失败均为请求层失败（空输出后同模型唯一端点被冷却，`no untried llm endpoint remains`），不是分析失败，但失败后既没重试，也没把原因分类暴露出来。

另有一类噪声：脱敏导致的永久缺口（原始模型请求、后端 HTTP）每次都被当成"本案缺证"。

## 1. 总体思路

- **先定协议，再调各轴。** 用一份 ≤2 页的数学抽象（与 `spec/alg/fulfilled.md`、`spec/math-abstract/judge.md` 同级）固定"哪个环节的偏差归哪个轴"。之后六轴描述与检查项都从这份协议派生，不再各写各的。
- **分工：分析轴偏召回，六轴偏准确。** 分析轴只摆事实、标可疑点、配好对照两端，不下结论；六轴只判自己那一环，证据不够可补查。
- **程序只校验、只标注，不改语义结论。**

## 2. 四项工作

### W1 六轴数学抽象（协议文档，关键路径）

产出：`spec/math-abstract/process-axes.md`，按 math-abstract skill 的产出合同写。核心内容预设：

- **执行链模型**：一次运行 = 节点（用户原文、路由/门控、模型决策、工具执行、外部数据源、上下文拼装、桥接/收尾、交付）+ 传递边（信息从一处到下一处）。
- **归属表（内核）**：每类节点/边唯一归一个轴。初稿方向：

  | 节点/边 | 轴 |
  |---|---|
  | 用户原文 → 系统内部表达（门控参数、任务表述、首批工具参数） | intent_understanding |
  | 路由、拆解、工具选择与顺序、失败分支、重试、终止；系统预算/准入/容量闸等**编排策略**；提示规则与执行规则不一致 | planning_routing |
  | 工具/后端/子 agent 自身执行（含内部解析模型、适配层） | tool_execution |
  | 外部数据源是否有所需数据 | knowledge_data |
  | 模型在**完整输入**下的决策与生成 | model_capability |
  | 结果投影、拼装、缓存、历史注入、截断；模型输出 → 桥接 → 交付 | context_memory |

- **判定规则**：偏差记到**首次出现偏差的节点**所属轴；多个节点各自真坏则各记，不去重；某节点没坏就不能记它。模型轴只对"输入经上下文轴判为无损"的调用成立。
- **值域**：每轴 `sound / problematic / not_evaluable / not_applicable`，写清各落点条件，穷尽无漏格；证据范围（scope）为空不得 sound。
- **翻译规则**：任何"这个用例要换个判法"的诉求，必须翻译成"节点类型不同"或"证据不同"；翻译不出来即协议变更，不按用例开例外。
- **边界裁定（判例）**：用 5–8 条已核实事实做试金石写进协议，候选：
  1. 系统预算/准入/容量闸按设计拒绝 → planning，不记 tool（D01 BUDGET、B01/B17 准入、B10 容量闸）；
  2. 工具返回他对象却标成目标对象 → tool + knowledge（B02/E02/E01/F01）；
  3. `EMPTY` 按业务期望判：按请求本就该空 → 正常；按期望应有返回却为空：查明是后台数据/知识缺失 → 只记 knowledge；查明是工具自身（解析丢条件、适配层不支持等）→ 记 tool；无法查明 → tool 与 knowledge 都记 problematic，finding 注明"原因未定位"（负例 vs B17 假空 vs 条款缺失）；
  4. 知识轴原因类型限定为：对象不存在 / 权限范围外 / 查询未执行 / 服务不可用 / 库无此条（wrong-empno 应为权限范围外）；
  5. 模型正确答复被桥接改义或替换 → context，模型轴不记（E01/E02/负例）；
  6. 输出格式违约看该次模型输入：输入已明确写清格式要求仍违约 → model；上下文构建有问题（格式要求缺失、被截断、相互冲突）导致无法按格式输出 → context；
  7. 无歧义时多余澄清 → model 决策（有提示依据时）或 planning，不记 intent（B10）；
  8. 单次工具耗时只能用该调用适用时限判断，不用整轮上限。
- **归位表**：把现有 checks、comparison 入口、降级规则各归到唯一位置；删掉的标注原因。

验收：你审归属表与判例；每条判例能在最新表中找到对应格子并给出唯一落点。

### W2 分析轴：容错 + 召回

- **容错（程序性）**：同端点退避重试，不因一次空输出就把唯一获批端点冷却出局。
- **重试后仍失败 → 整条 case 六轴 blocked**，不对着空气或残缺材料继续判。失败原因必须分类并显式暴露：请求层失败（端点/限流/空输出）、分析输出不合格（分析轴本身的问题）、需用户支持才能解决（如缺授权、缺采集）。事后整条 case 重跑；失败清单用于推动修分析轴或找用户解决，而不是产出不完整结果。
- **召回（分析质量）**：输出从"为各轴选材"改为**结构化可疑点清单**：每条 = 类型（状态变化、EMPTY/ERROR/拒绝、模型输出与交付文本不一致、同参重复调用、系统拦截等）+ 两端证据指针 + 涉及节点，不下结论。按 W1 归属表把可疑点分派到候选轴（可多派）。
- 约束：召回产出的是清单和指针，不是更多原文；六轴按需读取正文。

验收：7 类已裁定事件的关键证据对在清单中全部出现（召回）；清单体积不超过现有选材预算。

### W3 程序不改结论 + 缺口盘点

- **不改结论**：有有效证据的 fail 永不降级；引用失效、范围不全只加标注（`flags` + 原因），不改 status；重试沿用已读回执；pass 附带的永久缺口不触发降级。
- **导出**：每项检查的引用、缺口、标注原因进入 Excel。
- **缺口盘点**：统计 32 条中出现的全部缺口，分三类：
  - 平台永久限制（如脱敏后的原始模型请求、后端原始 HTTP）→ 协议里声明一次，作为 scope 说明，不参与判定；
  - 可补采（如逐次状态变化）→ 回到 trace 采集补；
  - 个案真缺 → 才算缺证。

  盘点结果交你拍板哪些忽略、哪些补采。

验收：同一输入下 fail 数不因程序处理减少；缺证项中程序降级占比可见且显著下降。

### W4 按协议改六轴并冻结重跑

- 六轴 `question/excludes/checks` 按 W1 归属表与判例重写，删掉与协议无关或重复的检查项（如上下文轴逐次模型调用的检查项在永久缺口下是否保留，由 W1/W3 定）。
- 在**同一批冻结 Trace、严格同模型**下重跑 32 条，逐格对照：检出、归位、理由是否有证据、同类是否一致、缺证是否合理；传输失败单列。
