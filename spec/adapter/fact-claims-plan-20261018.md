## 0. 原则

1. **先在进程内替换，不改正式文件。** 沿用 `report/d18-validation-20261017/exp_d18.py` 的做法：实验脚本 import 正式模块，在进程内替换提示词或函数，跑完还原。正式代码、spec、测试在门槛过了之后才改，一步一个 commit，反悔 = `git revert` 那一个 commit。
2. **固定上游，只变一处。** 每步只改一个变量；真实性轴结果能固定的就固定（跑一次存下来），主判多次重复（3 次）看稳定性。
3. **效果和效率一起报。** 每步都报两张表：结论对不对（对照人工核定）、花了多少（LLM 调用次数、工具调用次数、耗时；`AxisResult.usage` 里现成有）。
4. **门槛写在前面。** 每步先写"过了算什么、没过怎么办"，跑完对着看，不事后找理由。
5. **不碰工作区里别人的改动。** 实验脚本放 `report/fact-claims-20261018/`，不动 `impl/`。（10-18 晚：此前未提交的改动已进 `b1b81eeb`、`9e25fdaa`、`3c58be3a`，基线以 `3c58be3a` 为准。）

## 2. 分步

### 第 1 步：说法分主张和片段（提取改输出结构，不切原文）

> 2026-10-18 第一版写的是"提取提示词加一句拆单位"，实测没过（`report/fact-claims-20261018/RESULT.md`）：逐字摘抄下只能把"二十天"切成"犹豫期是二十"和"天"，正确回答被判出矛盾。根子在需求第一版把说法写成"一句话"，已改为"主张 + 片段"（需求 §2.1、C7）。本步按新定义重做。

**改什么**：提取（v8 落点 `knowledge_loop/extract.py`）的输出结构，每条说法两样东西：
- `claim`：主张，自由写法，断言了什么；不得含片段里没有的内容；
- `span`：原文片段，逐字连续摘自回答，可被几条说法共用；
- `context` 照旧只放对象标识（plan-20261017 §2.2-2 的定义）。
提取规则改成：一个数带的单位、币种、时点、所属对象，各自是一条主张，共用那段片段；"二十天""三十日"这类数带单位本身是一个量，是一条主张，不拆。
程序检查从"text 逐字在原文里"改为"span 逐字在原文里"；"context 不得含别条断言的值"改为按主张隔离：判定时只回答这条主张，片段里别的内容不顺手判。取证、判定按说法逐条进行，一段片段对应几条主张就查几次、判几次。进程内替换。

**看什么**：

| 指标 | 怎么算 | 门槛 |
|---|---|---|
| 原来对的不能变错 | A+B 16 条里旧链路判对的说法 | 新链路一行都不能变成 refuted |
| D 组拆对 | "1089.1 元" | 两条主张、同一段片段：值 verified，单位 unverifiable |
| 不该拆的没拆 | "犹豫期二十天""等待期三十日""一次""提前一天" | 各一条 |
| 变义 | 人工看 16 条：主张有没有超出片段的内容 | 0 条 |
| 漏抽 | 核心说法有没有少抽（上次 cashvalue 3/3 抽出 0 条） | 不比旧链路差 |
| 隔离 | 共用片段的几条主张，判定有没有判到别条主张的内容 | 人工看 D 组和 C 组，0 次 |
| 条数增长 | 每条回答的说法数，新 / 旧 | 平均多出 ≤ 2 条 |
| 效率 | 真实性链路 `llm_calls`、`tool_calls`、`elapsed_ms` | 涨幅 ≤ 条数涨幅 |

**没过怎么办**："原来对的变错"或"隔离"没过，说明判定读共用片段会串，试把判定输入里的片段换成"主张 + 对象标识"、不给片段；仍不行再回需求讨论。变义没过，提取提示词先收紧"不得超出片段"再跑一次。两次都不过，需求 §2.2 加 ⟡。

**反悔成本**：零，没改任何文件。
### 第 2 步：查不到的说法也带回执（加字段，不动枚举）

> 第一轮已过（RESULT.md 第 2 步）。v8 落点：`lookups` 由程序从取证案卷接出，不调模型；`found` 由取证提交 `submit_item` 时填。下面按 v8 写法保留，第 1 步重做后只需确认按说法（主张）而不是按片段填。

**改什么**：每条说法的结果加两个字段，`verdict` 三值不动：
- `lookups`：这条说法查了什么、返回落在哪（工具、参数、call_id），所有 verdict 都要有，程序从取证记录接出；
- `found`：`{object: true/false, attribute: true/false}`，返回里对象在不在、这一项在不在，取证提交时填。
`citations` 规则不变（unverifiable 仍为空），它只表示支持 / 矛盾的原文。

**看什么**：

| 指标 | 怎么算 | 门槛 | 第一轮 |
|---|---|---|---|
| 回执可回读 | `lookups` 里每个 ref 能对到一次成功、有返回的调用 | 100% | 111/111 过 |

**没过怎么办**：`found` 填不稳就退一步只留 `lookups`（回执是需求 §3.3 的硬要求，`found` 是方案层的 ⟡1）。
