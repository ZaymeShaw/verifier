# 整理证据与同会话纠错（2026-10-04）

用户确认：证据只引用实际查阅且支持当前陈述的记录。消息 A 包含关联调用编号 B，不代表查阅过 B；陈述仅依赖 A 就引用 A，需要 B 的输入、耗时等事实时再读取 B。关联关系继续保存在原记录与程序环节表中，无需增加模型填写的关联字段。

## 实现

Agno 案卷的 trace_analysis 评测入口复用 process_loop.analysis.Analysis，通过既有 LlmClient.complete_step 与 ToolLoop 执行。每次 submit_structure 校验引用读取回执及结构，被拒后保留原会话、工具返回与候选结果，模型补读、修改引用或收窄陈述后重新提交。查阅与提交同批发生不算查阅到正文，须下批提交。错误编号不由程序自动剔除，非法发现不再 salvage。工具预算耗尽或持续未提交则整理失败，下游按原依赖机制阻断。

原角色仍为 judge，reasoning_effort=medium。现有 600 秒请求超时现在约束 complete_step 的单次请求尝试，不再罩住多轮取证 Agent；整理轴仍用 7200 秒总预算，在每次请求前后检查截止时间。端点重试由原客户端负责，重发当前请求，不重放已执行的取证工具。工具预算 12 次，包含提交及被拒调用。

读取回执与提交是否接受、拒绝原因保存在 structure.evidence_audit 中。读取回执证明实际提供了哪些片段，不认证这些片段支持模型陈述，语义正确性仍须人工/模型评测。

## 工具记录配对

AgnoReader._start 优先顶层 start_time，再用 metrics.start_time，最后才用 created_at。保单原例的 API 记录 created_at 接近结束时间，原优先级将三次同名同参执行配错；修复后 tools/1、2、4 分别对应 spans/4、6、11，开始时间差小于 1 毫秒。

## 验证与限制

保留原整理测试的全部 24 个函数和参数化样本，将原 complete_json mock 更新为脚本化 complete_step。原自动删减成功预期改为拒绝或明确失败，补充独立回归覆盖 A/B 引用两种修正、原会话保留、发现保留、同批读取限制、预算失败和请求边界截止检查。另有真实 Agno SDK 到临时本地假 OpenAI 服务的入口回归。

原保单首轮历史回放：9 次原取证工具调用 + 2 次提交；首次拒绝两个额外引用后，脚本提供仅引用已读证据的候选，10 条路线和 8 条模型发现全部保留。回放不请求真实模型，不能据此承诺实际调用数、耗时或业务结论语义正确。

未修改 llmtracing 或 LiteLLM 实现，未改运行数据、.env 或正在运行的服务。完整重新评测需在服务加载新代码后进行。

## 分析轴交付完整材料（后续优化）

分析轴在submit_structure接受后，通过prepare_selections按环节确定性准备每轴materials。整理模型的读取回执仍约束它的陈述；交付程序从完整案卷提取环节两端、相关组件/工具定义、当次工具span说明和耗时，不依赖候选召回，不摘要或裁切。共享重复正文，审计中记录实际交付路径。

独立Agno六轴消费materials分组，无取件工具。每组完整环节不可被拆开；80k仅是分组目标，超大单环节保留并标oversize。每组及总结果严格覆盖义务×环节；格式重试仅作用于当前组。未交付正文引用不能支撑通过或不适用结论。

模型环节优先精确请求；消息文本与工具调用保持原记录。采集时组件/工具定义保留scope=observed_at_collection_not_verified_run_version，不能认证当次模型已收到规则；其他调用的输入也不代表本次已知。非模型轴判准版本同样须核对，不能把采集时背景冒充当次配置。

相关231项回归通过；历史案卷离线递归还原逐字段相等；四个真实合成模型轴对照符合预期。完整历史六轴尚未在线复测，不能宣称整体质量无退化。大编排材料有成本和长上下文风险。现有嵌套ToolLoop与transcript路径保持各自合同。
