# Judge 判定逻辑的数学抽象（不变式内核 J 与映射管线）

> 状态：抽象层协议。本文只固化判定逻辑的数学骨架——什么是不变的、什么是可替换的，
> 不是实现计划。业务语义以 `spec/alg/fulfilled.md`（轴1）、`spec/alg/capability_carrier.md`
>（轴2）、`spec/alg/authority.md`、`spec/alg/material-positioning.md` 为准；
> 本文与它们冲突时，以各协议第一章为准，回来修本文。

## 1. 不变式内核 J（即轴2 的数学抽象）

整个判定体系收敛到一个内核：

```text
J(未达成期望, 能力空间快照) → 三态 + 自认 + 引用
```

注明：J 就是轴2（能力承载判定，`spec/alg/capability_carrier.md`）的数学抽象——
三出口即轴2 的三态，不存在另一套判定。本文通篇写 J 的地方，读作轴2 即可。

记：

```text
J : F × G → V
  F   未达成期望（一条；不折叠，多条各判各的）
  G   能力空间快照（一组可问责断言：每条断言带出处/信任档位/新鲜度的戳记，§6）
  V   三态 × 自认 × 引用
      三态 ∈ { 做不了, 做错了, 说不清 }
      自认：判"做不了"必须携带资料层自认证据（缺维度/缺值/缺操作符/is_supported=false
            或形态等价物），live 话术不算；
            对称地，判"做错了"是合取推导——该期望未达成 ∧ G 证明承载得了，
            证据同样只从 G 取，不看交付内容（§7 第 2 条）
      引用：每个结论携带可回溯 citations，且落在 provider 声明的引用空间内；
            "说不清"必带差在哪儿 + 成因（缺料，或期望与能力空间的口径分歧）
```

G 的定义以可问责为准：G 由可问责的断言构成，每条断言自带戳记（出处 / 信任档位 /
新鲜度，§6）。文档、代码、受治理 YAML 等资料是断言的**历史载体**——记录断言从
哪儿来、由什么担保——不是 G 的构成成分；载体可以更换，戳记完整的断言集才是 G 本身。

J 的关键性质只有一条：**J 不关心两个实参是怎么来的。**

J 的定义域就是"一条未达成期望"和"一份能力空间快照"这两个值本身。
快照是 YAML 装载的、探针探出来的、还是调用方声明的——这些差异全部被压进
断言的戳记（§6），不进入 J 的判定逻辑；期望从哪儿来 J 同样不问——
它拿到的只是 F 里那条期望值（e 的戳记规则见 §6）。
这就是"揣测不越轴"的数学形态：J 没有旁路输入，想偷看这次交付了什么、
live 说了什么话，在类型上就办不到。

## 2. 轴1 作为映射模式

轴1（办成了没有）在本框架里不是另一个判定内核，而是一组映射的复合：

```text
d(·) → 交付快照        d : X → D    x = live 一次运行的原始现场
e(·) → 期望集          e : Y → E    y = 需求侧输入（用户诉求、业务上下文、reference 线索）
C(d(x), e(y)) → 达成/说不清/未达成 + 未达成期望集
                       C : D × E → { 达成 } ∪ { 说不清 } ∪ ( { 未达成 } × P(E) )
```

复合起来：

```text
f = C ∘ (d, e)    f(x, y) → 未达成期望（集）
```

C 是比较器：拿交付快照对期望集逐条对账，三出口"达成 / 说不清 / 未达成"穷尽
（§7 第 6 条），并把未达成的那部分期望原样交出。轴1 的输出不是一个分数，
而是**一个集合**——正是这个集合作为 J 的第一实参喂给轴2。
轴1 判"达成"或"说不清"的 case，未达成期望集为空或未定义，
J 不适用、不跑（结构保证，非纪律要求）。

## 3. 完整管线

```text
J( C(d(x), e(y)), G ) → 三态 + 自认 + 引用

其中  G 是 J 的一等实参：可问责断言集（每条带 §6 三件套戳记）
      z = 项目的资料现场（担保空间，可选）
      w : G ⇀ Z    偏担保关系——断言回溯到为它背书的材料
```

G 直接作为 J 的第二实参供给，不必然经由某一次 g 计算派生。z 是可选的担保空间：
资料现场（文档 / 代码 / YAML / 探针记录）通过偏关系 w 为断言提供担保——
"这条断言拿什么背书、可回溯到哪份材料"。w 是偏关系：个别断言可以暂缺担保
（相应落低档，§6），但担保空间本身**显式保留、不删**——删掉 z，可核验性就从
结构保证退化为合同约定（只剩"供给方说它可问责"），这是不许的。

展开为数据流：

```text
x（运行现场） ──d──→ 交付快照 ─┐
                              ├─ C ──→ 达成 / 说不清 → 结束（J 不适用）
y（需求侧）   ──e──→ 期望集  ─┘        └──→ 未达成期望集 F
                                              │（逐条）
G（可问责断言集，已戳记） ────────────────────┤
  ┆                                           ↓
  w（担保，偏关系）                     J(f_i, G) → 三态 + 自认 + 引用
  ┆
  z（资料现场：文档/代码/YAML/探针记录）
```

时序约束是管线固有的：G 在判定时定格（同维度同快照幂等）；
J 在 C 完成之后运行（判后派生）；J 的输出永不回流到 C 的任何输入。

## 4. 判定逻辑唯一，项目差异只在 provider

```text
项目唯一的：J 和 C ——判定逻辑本身
项目各异的：d / e / g 的 provider ——三个映射怎么实现、从哪取数
```

这是本框架的分层定理：任何"这个项目判法不一样"的诉求，
都必须先被翻译成"这个项目的 d / e / g（或其物料）不一样"。
翻译不出来的，说明它试图修改 J 或 C 本身——那是协议变更，
走协议评审，不走项目接入。

反过来，接入一个新项目的全部工作量 = 提供三个映射的实现：
交付快照怎么取（d）、期望集怎么来（e）、能力空间快照怎么建（g）。
J 与 C 一行不改。

g 有合法下界：当项目已持有戳记完整的 G（每条断言带 §6 三件套），
g 的最小合法实现就是校验后恒等交出。真正的最低要求是**可问责的 G 本身**，
不是 g 的这次计算——g 是把 G 建出来或验出来的手段，不是 G 合法性的来源。

## 5. 既有机制的归位：都是 provider，不是第二套判定逻辑

现有各机制在本框架下各有唯一位置。它们不是不同的判法，
是同一个 J / C 的不同供料方式：

| 既有机制 | 归位 | 说明 |
|---|---|---|
| 受治理 YAML 物料 + `key_live` 消费 | G 的供给方 | 按稳定 key 实时取数，源漂移自动吸收；快照 revision 进审计 |
| source 阅读（调查期读源码/文档） | G 的供给方 | 产出的是带戳记的断言，进能力空间；不产出结论 |
| `llm_probe` | G 的供给方 | 探针探测得到的能力断言，同样带出处与信任档位入 G |
| caller-stated（调用方声明的能力/边界） | G 的供给方（叠加层） | 档位随担保强度定：无独立担保时只落低信任档叠加层，或作注意力提示；不准进轴1 计分（§7） |
| 调查资料（investigation 产物） | f / g 输出的缓存 | 是映射输出的物化缓存，带 staleness；缓存过期 ≠ 判定逻辑变化，按漂移协议重算/重验 |
| adapter / live / show_schema | d 的 provider | 交付快照怎么从运行现场取出来，是 d 的实现细节 |
| judge_boundary | f / g 的定义域声明 | **不是 provider**。它声明哪些期望进得了 F、哪些资料算得上 G（定义域），不供任何值 |
| Runtime `authority.resolve`（in-run scopes，默认全关） | 治理裁决通道（非 provider、非 J） | 裁决职责/能力/口径类标准问题，产出带担保的 resolved statement；不产 J 的三态。其结论对轴1 三态的确定性落位由 fulfilled.md §3/§3.1 定义（authority 开启模式），与 J 的三态归位是两条互不冒充的通道 |

归位的判别式：一个机制如果**供出一个值**（交付、期望、能力证据），它是 provider；
如果**限定哪些值合法**，它是定义域声明；如果**下三态结论**，它就是在冒充 J——不许。

## 6. 戳记规则：三件套只构成 G

戳记三件套（出处 / 信任档位 / 新鲜度）是 G 的成员资格，不是三路映射的共同纪律。
三路各有其规则：

**G：三件套即成员资格。** 没有戳记的断言不是 G 的元素——不存在"先入 G、再补戳"
的状态。担保是另一回事（§3 的偏关系 w）：断言可以暂缺担保、相应落低档，
但戳记本身构成断言的可问责性，不可缺。

```text
出处（provenance）      断言从哪份资料/哪次探测/谁的声明来，可回溯
信任档位（trust tier）  档位随"谁担保 / 担保多强"定，不由内容类型单独决定；
                        normative_rule / external_fact > inlive_boundary > current_behavior
                        的定位序保留为典型担保强度的缺省映射，不是档位的定义；
                        caller-stated 无独立担保时落低档
新鲜度（staleness）     断言定格于哪个 revision / 探测时刻；源漂移后按消费模式路由
                        重算/重验。新鲜度只在 G 上有意义——只有能力断言有
                        "钉在哪个版本"的问题
```

**e：默认无戳记。** 期望取自需求侧输入 y，出处结构上就是诉求文本本身，无须显式携带；
期望默认字面闭合。只有当 e 附加超出诉求字面的口径（派生解释）时，那条口径必须带
担保/出处；给不出担保的口径不得进入 E。这是对 e-provider 的**装配期合同要求**
（provider-contract §2.2），不是判后审查项——由产出口径的同一判定者判后自报
"是否超字面"、再按自报强制降级的方案已被证伪（§8）。有担保口径彼此冲突、
读法分歧材料定夺不了，属 semantic_mapping 类治理问题：authority 开启时由其裁决
（fulfilled.md §3.1），任何情况下不许判定者静默择一；已给出有担保口径时
判定必须按口径消费，常识不得改写或绕开。
e 只消费 y——caller-stated 不是 e 的来源、
不得给轴1 洗分（§7 第 3 条）；给期望加三件套也造不出第二个 G，期望不是能力断言。

**d：无戳记合同。** 交付快照的出处结构上就是本次运行；C 不消费信任档位与新鲜度；
J 永不看 d(x)（§7 第 2 条）。给 d 的输出加戳记没有消费者。

J 消费 G 戳记的方式是确定性的：**g 缺失或低置信 → 诚实的"不确定"（说不清 + 差在哪儿 + 缺料），
不是一个自信的错误结论。**没有查证过 ≠ 查不了；低档资料不能解除高档问题的 Gate；
资料不够就说资料不够，把缺料清单留给人，而不是让 J 用常识补齐。

这条规则是内核不变式的对偶面：J 不关心 G 怎么来的（§1），
恰恰因为每条断言把"怎么来的"带在身上，J 只需按档位与新鲜度确定性地降级或拒判。

## 7. 结构性约束（轴1 vs 轴2）

以下是抽象层的硬约束，不是代码规范：

1. **轴2 判后派生，永不改写轴1。** J 在 C 完成后运行；J 的任何输出不回流到
   C 的实参、不改 C 的结论、不进轴1 计分。轴1 判定时 J 的通道物理上不存在。
   能力/职责的治理裁决（authority in-run scopes，默认全关）不是 J 的通道：
   开启时它如何参与轴1 三态由 fulfilled.md §3/§3.1 定义（§5 归位表 authority 行），
   不构成对本条的违反，也不得借此把 J 的输出偷渡进轴1。
2. **J 永不查看本次交付。** d(x) 不在 J 的定义域里。"做错了"是合取推导
   （未达成 ∧ 承载得了），不是 J 看了交付内容判出来的。
3. **caller-stated 只进 g / 注意力，不进轴1。** 调用方声明可以作为能力空间的
   低信任叠加层，或作为提示 Judge 注意某处的信号；不得作为 e 的来源、
   不得给 C 的对账结果洗分。
4. **"自认"只认 G 内可问责的承诺。** 本次 live 的话术不构成担保——"暂不支持"
   的现场说辞不能自我背书为承载性证据；防循环格挡体现在担保上
   （被测系统自己说"是"的东西是被量的对象，不是尺子）。
5. **单位是期望，不折叠。** F 中每条期望独立过 J；case 级只做罗列展示，
   不定义 case 级单值。
6. **覆盖无漏格。** C 三出口穷尽 → 只有未达成进 J → J 三出口穷尽且
   "说不清"成因穷尽。任何案子都有唯一落点。
7. **provider 失败 ≠ 说不清。** 映射运行失败（装载失败、重试耗尽）是本次运行
   error，不得伪装成 J 的"说不清"业务结论。

## 8. 演化含义（简记）

本文主体是抽象逻辑框架；对实现演化只留两句方向性的话：

- **provider 合同一等公民化**：d / e / g 的接入合同（值 + §6 分路戳记规则 + 引用空间声明）
  应当是显式的、装载期可校验的一等对象，而不是散落的 getattr 约定；
  合同正文见 `spec/math-abstract/provider-contract.md`；
- **把硬依赖剥成 provider**：凡是 J / C 附近直接摸具体物料、具体项目函数的地方，
  都是待剥离的隐式 provider，逐步收敛到 §5 的归位表里。

其中 e-provider 的显式拆分是已识别、刻意暂缓的待办。§6 的口径义务当前**没有**
运行期执行机制：判后自报方案（期望的 interpretations 字段 + 口径 gate 按自报
强制 说不清）已于 2026-08-26 实施并当日回滚——触发条件"是否超出字面"不可由
产出口径的同一 LLM 自判（在业务本身即语义映射的项目上自报趋近全量），
fail-closed 使诚实上报自毁（冻结集 24 case 误杀 23，真实 F/NF 信号被抹平）。
教训固化为约束：口径义务只能在装配期结构化担保（e-provider 拆分后由装载期
合同校验），或由 semantic_mapping scope 的 authority 裁决承接，不得再走判后自报。
动手拆之前必须先想清楚三件事：
(1) 收益条件——只有当口径装配需要在判定前独立运行（口径板批量引用、
e 输出跨 case 复用/缓存、期望集独立评审）时才值得拆，不为拆而拆；
(2) 合同不重写——provider-contract §2.2 的 e 路输出（默认无戳记、
附加口径带担保、分歧显式标记）就是拆分后的运行期合同，缺的只是装载期声明
（供哪一路 / 引用空间 / 失败面）；
(3) 拆分不得改变的东西——C / J 一行不改，期望仍只消费 y，
不得因拆分给 e 输出加三件套造出第二个 G。

实施细节（分层拆分、fail-fast、形态族）见 `spec/alg/capability_carrier-generalization.md`
的既有方案，不在本文重复。
