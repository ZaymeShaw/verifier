# 2026-11-04 demand 修订：说明回合按任务配置（2026-11-04 用户确认，已并入正文）

起因：8036 33 条重跑（job `ff2417a8`，2026-11-03）的调用记录里，兑现和 6 个过程轴（实际）每个 case 都走说明回合：程序先不收、把结论回给模型，模型把整份结果重交一遍。165 次里 159 次除 reason 外一字不差，每次 1–2.5 千字。

拿模型第一次交的 reason（没看结论）和最后收下的 reason（看过结论）对比：

- **兑现（33 对）：** 程序回的是每条期望的兑现状态和依据，来自真实性、知识查证、过程轴的结果，模型交的时候不知道。第一次的 reason 至少 5 处和程序结论矛盾（3 处总判断说反，如 `axes-6602b41666c6` 写"两项期望均已兑现"，程序判 not_fulfilled；2 处单条期望状态说错）。说明回合必须保留。
- **过程轴实际（132 对）：** 程序回的是 verdict 和计数，都由模型自己交的条目推出。第一次的 reason 和结论 0 处矛盾；看过结论后的改动主要是加"最终结论为 xxx"和计数复述，而本轴说明本来要求"不复述'达到几项'这类计数"。

用户定（2026-11-04）：要不要把程序结论回给模型、让它看过再写说明，不在需求里定判断标准，按任务配置；配不配按场景需要定。
