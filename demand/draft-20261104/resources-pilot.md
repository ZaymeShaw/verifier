## 1. 起因

8037 新配置 22 条（job `32f579f9`，langfuse 现场 11 + 按 trace 复评 11）的调用记录：

- **被拒的引用 104 处，全是过程六轴（实际）引 trace 记录**（这批没开核事实，知识源一次没调）。逐条对照模型当时看到的内容：真抄错的约 12 处；其余约 92 处模型抄的就是它看到的，只是核对认的范围更窄——
  - 42 处：抄了带键名的 JSON 片段（如 `"polno": "P260922000005855"`），核对只认字段值；
  - 25 处：抄了记录的元信息（如步骤名 `agentic-insurance-qa-agent.backend.policy.search`），核对只认 fields；
  - 22 处：引了在别的轴材料里读到的记录（过程实际 6 个轴一个上下文、都能读），核对只认本轴材料，推送里也没说；
  - 3 处：原文就在本轴字段里也被拒，原因未查。
- **已被接受的过程轴引用里有隐患**（能对上原记录的 301 条）：40% 在所引记录里出现不止一处，21% 同时出现在 input 与 output，17% 只有 6 个字以内；只核"在不在这条记录里"证明不了引的是哪一处、哪一端。
- **口径不统一**：需求只定了一种引用规则（§3.4 第 2 条：原文逐字出现在那次调用中模型实际看到的返回里），实际有 5 种引用写法、3 种"原文"范围、3 套比对时的宽容规则，给模型的说法互相矛盾（系统规则 4 说出处写调用编号或材料标题，过程轴提交格式说只写记录编号）。人照着写也会晕。
- **代价**：引用被拒后重交、为改引用去读材料，22 条合计约 900 秒（26 次请求）；写引用字段约占可见输出的 24%。

## 2. 试点要回答的问题

1. 按本文的规则重核，那 92 处误拒能消掉多少；
2. 能抓出多少"对上多处、分不清 input / output"的隐患，抽查下来是不是确实该拦；
3. 原来该拒的真错误会不会被放过；
4. 统一成"地址 + 区间"后，引用的位置、歧义、角色能不能一致地算出来。

## 3. 概念与边界

| 名字 | 是什么 | 不管什么 |
|---|---|---|
| 资源 | 能被读、被引用的一块数据：有地址，内容按统一格式 | — |
| 资源类型 | 按数据形态分的通用类型（如记录集、键控列表、JSON 树、文本），规定一类形态怎么摆成层级、怎么列目录、怎么在一块里找原文。**全部由框架提供，与业务无关** | 数据从哪来 |
| 地址规范 | 地址怎么写：前缀表示类型，路径表示层级，`#` 后表示块内位置；怎么找上一级、怎么列兄弟。各数据按规范做自己的地址映射 | 具体数据 |
| 挂载 | 在框架定的时机，把动态产生的数据按某个资源类型交给框架，变成这个 case 的资源 | 怎么切、怎么摆（类型的事） |
| 资源白名单 | 每个任务能读哪些地址（读取范围）、能引哪些地址（引用范围）；由现有材料白名单扩展而来 | 内容对不对 |
| 资源工具 | 列目录、读、搜、核对这一组能力，模型调用与程序直接调用共用一份 | 判断对错 |
| 引用规范 | 引用怎么写、怎么核；所有引用都按它来 | 引文支不支持结论（各轴业务规则的事） |

**和信息源的边界**：信息源管"拿数据"（连哪个系统、调哪些工具、怎么采集）；资源管拿到之后"怎么摆、怎么读、怎么引"。**数据谁产出，谁负责挂载**：每个信息源在自己的 provider 约定里实现挂载（与 `collect`、`open_reader` 并列）；内置材料由内置材料注册表挂；轴的结果由框架挂。框架只定接口与时机。没实现挂载的信息源，它的数据不进资源，不能按资源方式被引用。

## 4. 原则

1. **读出来的文本与核对用的文本是同一份。** 每块资源有一份固定的规范文本（同一数据每次序列化完全一样）；读工具返回什么，核对就在什么里找。
2. **引用在程序内部统一存成"资源地址 + 文本区间"。** 模型写地址，必要时加一句块内摘句；**不让模型写位置**，位置由程序换算。生成规范文本时同时记下每个字段、每项元信息占哪段区间，由区间判断引的是哪个字段、属于输入端 / 输出端 / 元信息。
3. **摘句在所指的块里只能对上一处**；对上多处就拒，让模型多摘几个字或把地址写细。
4. **没看到的不能引**：此前没读过的块、只给了预览的部分不能引（读过什么从调用记录里查，不另建账本）。
5. **核对只有一个公共入口**：地址存在 → 读过 → 在引用范围内 → 摘句换算出区间 → 只对上一处 → 记录角色。宽容规则全系统一套。不通过时给出修改提示（最接近的位置），模糊匹配只用来提示，不用来放行。
6. **"支不支持结论"不归引用管**，仍由各轴业务规则判。

## 5. 试点范围（P1：离线复核）

- **只做**：一种资源类型（记录集）× 一个信息源（langfuse，在它的 provider 约定里实现挂载）× 一类引用方（过程六轴实际）。
- **只用录好的数据**：8037 那 22 条的调用记录与案卷，拷一份用；不碰 8036 / 8037 实例数据。
- **不调模型**：从调用记录里取模型当时实际读到的返回作为那一块的文本，按本文规则重核过程轴全部引用（被拒 104 处 + 已接受约 300 处）；每条引用都算出"地址 + 区间 + 角色"。
- **不改现有**：轴配置、提示词、提交格式、现有校验、读证据的工具、前端、其他信息源都不动；新代码不被现有代码引用。
- ⟡ **跨轴引用**（在别的轴材料里读到的记录）允不允许引：P1 两种规则各算一次，看结果再定。
- ⟡ **元信息**（步骤名、类型、状态）能不能引：倾向能引（模型确实看到了，且"调用了哪个工具"正是判断依据）；P1 按能引算，同时单列这部分数量。
