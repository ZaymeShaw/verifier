# 业务 Trace：Langfuse 需求

> 状态：2026-10-20 上线（修订记录 `spec/implementation/demand-revision-20261020/`，旧版备份 `demand/backup-20261020/`）。原文的映射、关联字段、采集流程、Insurance 现状、部署与实施状态都是方案或实施，已拿出（见 `去向.md`）。
> 上游：`demand/demand.md` 第 7 条、`information_sources.md`（trace 要满足什么）。

## 1. 要什么

很多被测系统用 Langfuse 记录运行过程，既不用 Agno，也不经过模型中转。评测要能取回这些系统**每一轮的过程记录**，用在过程六轴、主轴等需要 trace 的地方，效果和已有的 trace 来源一致；不要求业务换框架或改接中转。

## 2. 要满足什么

1. **精确关联到这一轮**（`information_sources.md` §4.2）。
2. **采到什么程度要看得见**（`information_sources.md` §4.4）。Langfuse 特有的几种缺口都要标出：写入是异步的、业务可能开了采样、内容可能被脱敏或截断、没埋点的步骤看不见。
3. **记录的不等于实际发生的。** 记录里的模型输入不一定是真正发给模型的原文；没记录不等于没发生。这些限制要随结果一起交给下游。
4. **业务自带的评分不是评测结论**（`information_sources.md` §1.2）。
5. **改业务只为关联**（`information_sources.md` §4.8）。
6. **不回归。** 已有 trace 来源的产出不变。

## 3. 不做

- 不把评测结果写回 Langfuse。
- 不读 Langfuse 的 prompt 管理、数据集、实验。

## 4. 验收怎么看

- 用真实业务跑通单轮、多轮两种 case，从取回到六轴、主轴全程可用。
- 同一批 case 与已有 trace 来源对照，六轴结论一致或差异说得清。
- 关联失败、没采齐、内容被脱敏或截断时，各处输出缺证或降级，不当成通过。
- 已有来源的测试与快照产出不变。
