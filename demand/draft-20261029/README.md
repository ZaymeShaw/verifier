# 2026-10-29 demand 修订：唯一性原则（2026-10-29 用户确认，已并入正文）

起因：8036 mcp 11 条全量（job `2e4f9747`，2026-10-28）F01 上下文超限、C08 超墙钟，两条没出结论。查下来：

- **说法重复。** F01 最后一轮的回答把同一张保单的内容说了三遍（业务把英文推理、草稿和正式回答一并交了出来；起初误记为"三轮回答各说一遍"，2026-10-29 核对原文后更正），每遍各列一条、各取证一次：60 条说法，按"同一对象、同一件事"归并后 40 件；15 组重复全是同一对象、同一个值，没有前后说法不同的。
- **取回的内容重复。** 一次 25 条说法的取证返回 18.3 万字：引文所在整条记录占 74%，其中 21% 是同一条记录随不同说法各带一份；引文本身 4%，末尾又整份抄了一遍（9%）。
- **查询不全是重复。** C08 取证里换着词查保单 11 次，大多数是因为前一次没查到对的东西（只写"保单"返回未执行；带客户编号返回的是别人的保单——评测方工具丢客户编号，已知问题）；真正重复的只有已经查全之后又查一遍。
- 现有需求只在 `axis_loop.md` L7 管到"同一份材料反复灌给模型"，任务交的结果、工具返回没有管。

用户定（2026-10-29）：优先解决重复；原则名"唯一性原则"，带定义使用。

**新增 §3.8：**

> ### 3.8 唯一性原则（2026-10-29 用户定）
>
> **同一个东西只给一份，用到它的地方引用这一份。** "同一个"看实质：同一个对象、同一件事、同样的内容；换了叫法、编号或措辞，说的还是那件事，也是同一个。内容不一样就不算重复（例如上一次没查到，换个方式查回了别的结果）。只去掉重复的部分，判断要用的内容不少给。
>
> 适用于任务交的结果、loop 里的工具调用和返回、交给模型的材料。轴说明里用到这条原则时，定义一并写上，不只写名字。

**§8 加一条：**

> - 不让同一个东西在任务结果、工具返回、材料里出现两份；也不为了省而少给判断要用的内容。

**§9：** "L1–L9 每条都能在方案里找到对应的处理"改为"L1–L10"。
