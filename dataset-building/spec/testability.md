# 需求—供给匹配下的不可测排除方案草案

状态：2026-11-02，待验证。对齐[需求](../demand/testability.md)。本次确定了问题表述与探索方向，尚未证明一种自动判定方法可靠。

## 方案假设

优先寻找“必要需求与环境供给存在确定冲突”的依据，而不是逐题尝试完成任务，再根据结果判断可测性。

这可以减少必须完整解题或证明全部条件具备的负担，但不会自动解决探索边界问题。必要需求可能识别错误，供给范围可能不完整，判读证据的过程也受标注者能力影响。以下流程均为待验证假设。

## 最小判定过程

1. **读取原题和已有标注。** 保留完整对话，不因来源类型替代题意判断；沿用已有无效题过滤信息。
2. **识别可能的必要需求。** 用一句话说明任务必须得到什么，而不是预设工具调用序列。只需调查能支持明确排除的需求，不要求先穷尽所有需求。
3. **匹配已知供给。** 查批次共享的环境说明，区分“已知有”“明确只有”和“未知”；保留资源内容与访问限制的区别。
4. **检查阻断依据。** 确认需求的必要性、供给限制的适用范围以及是否存在未排除的允许替代路径。缺少其中任何一项，不下确定排除结论。
5. **记录结论。** 有充分阻断依据则确定不可测，否则不确定；指出缺什么证据，便于以后继续检查。

停止调查与下排除结论分开。预算用完、某次查询失败或已经完成预定层级，只能结束本次调查，不能自动证明不可测。

## 信息阶梯

阶梯表示本次依据来自哪里，不是置信度等级，也不是每题必须执行的流水线。信息可以组合使用；后续信息更多不保证原结论正确。

| 信息层级 | 可以做什么 | 不能据此做什么 |
|---|---|---|
| 题目与已有上下文 | 识别依赖；在输入范围和获取限制已经明确时，判断是否缺少不可替代的信息 | 仅因附件未出现在题面、问题简短或有指代就排除；若可另取资料或原目标是澄清，仍需另判 |
| 环境能力与限制 | 核实授权范围、允许途径、接口能力和明确不提供的资源，与必要需求对照 | 把工具清单当完整能力边界，或把当前执行者失败当供给不存在 |
| 具体资源与访问证据 | 在明确范围内检查实体、字段、版本、原文和实际访问限制 | 把一次检索未命中、局部页面或单库缺失当全环境缺失 |

**当前优先探索第一层**：只使用题目、现有上下文以及已经明确的边界，不为每题启动联网探索。不补造供给假设；若能确定排除的题很少，这是允许的结果。后两层记录为后续扩展方向，不在本次文档调整中实施。

## 供给说明与判定记录

先使用可读文本和简单表格，不设计独立配置平台或通用规则引擎。

批次共享的供给说明包含与任务相关的身份、允许资源和访问方式、明确限制、未知项及版本/时点。每条限制应有出处；清单没有出现某资源，并不默认该资源被禁止或不存在。

逐题记录：

| 项目 | 内容 |
|---|---|
| 题目与环境引用 | 原题标识、完整上下文、供给说明引用及相关版本/时点 |
| 必要需求 | 一句话及其为什么不可缺少；允许替代途径尚不明确时注明 |
| 相关供给事实 | 资源与可达性的已知事实，区分存在、明确限制、未知 |
| 排除结论 | 确定不可测 / 不确定 |
| 理由与依据 | 确定冲突或当前不能确认冲突的原因，附可定位证据 |
| 所用信息层级 | 本次实际使用了哪些信息，不伪装成已探索完整环境 |

这些是记录内容，不是已实现的 schema。对外呈现仍可压缩成需求文档中的四列。

## 检查边界的对照例子

| 必要需求与供给事实 | 本阶段结论 |
|---|---|
| 要比较两份指定材料；已确认其中一份未保存，且指定环境没有其他允许的获取途径 | 确定不可测，阻断是缺少必需材料 |
| 同一任务只知道题面没附材料，环境是否可获取未知 | 不确定 |
| 需要某项条款信息；源库包含它且允许直接读取，但某次 RAG 未命中 | 不确定，不能据此排除；本阶段不升级为可测 |
| 同一信息只能经指定 RAG 访问；已经证明其唯一允许路径不提供必需内容 | 确定不可测，仅对该供给范围及相关时点成立；如何证明仍待验证 |
| 某库中没找到信息，是否还有其他允许来源未知 | 不确定 |
| 需要具体客户数据，查询返回零条，但解析、权限和数据范围尚未确认 | 不确定 |

源知识与系统访问方式是供给的两个变量。改变允许访问方式是环境对照；取得更多证据是信息增量实验，两者不能混作同一方法的效果提升。

## 如何验证这个方向

下一轮先检查第一层能否形成可复核的排除，而不是重跑全量探查。下列内容是实验设计候选，尚未执行。

- 保留同一原题，构造或选取有明确依据的供给描述对照：“已知有这些资源”“明确只有这些资源”“范围未知”。观察是否因清单缺项而错误排除。
- 对缺上下文、附件、实体信息和开放任务等边界案例，复核所谓需求是否真正必要，是否把澄清任务或可替代路径误判为阻断。
- 将判断记录交给独立复核者，检查每个排除能否追到明确冲突。人工复核也是有限手段，不被视为已经证明边界穷尽。
- 随后在供给范围不变的案例上追加资源证据，检查不确定能否被合理推进，以及错误排除能否撤销。若改变环境，单独记录，不算信息增加。

重点记录排除数量、排除依据成立的比例、误排除案例、不确定数量、复核分歧和成本。有独立参照时再统计遗漏的不可测案例；没有参照不报告准确率。不确定表示保留调查空间，不等同于错误纳入可测集。

模型、样本规模、具体提示词、调查预算及停止门槛均未定。不能仅用“更强模型”“人工看过”或“多查几次”宣称方案已可靠。

## 首轮 A/B 的定位

[首轮实验](../experiments/20261102-testability/README.md)探索了 A（题意＋静态工具清单）与 B（增加只读探查）。A 得到 24 条候选、4 条待确认；B 分为 2 条资料较明确、11 条限定范围、2 条疑似工具问题、13 条待核实。

它揭示了非空返回不等于供给满足、查询失败不等于供给缺失等局限。实验未固定充分的需求—供给边界，没有独立金标，不能证明 B 更优，也不能将其四个分组直接转换为当前两个标签。原始结果保留为历史记录，不追改标签来制造新方案效果。

## 未解决的问题与实施范围

仍需解决：必要性的判断、供给范围完整性的依据、替代路径处理、访问限制如何得到足够确认，以及何时停止而不制造假确定性。按依赖类型划分、人工判读、分层探索只是候选手段，都不能自动解决这些问题。
