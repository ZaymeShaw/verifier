本次“无供给”仅指评估者看不到信息源内容；被测环境仍有这些源。没有访问业务数据库、知识库或被测聊天服务。

## 真实题结果

从聚类采样后的人工对照保留池 1,061 题中，以固定种子 20261105 按 7 类来源抽取 50 题，一次请求提交。其中 12 题多轮。来源等额抽样用于探索，不估算全库可测率。与旧 28 题探索重叠 3 题，但没有向模型提供旧标签、工具输出或报告。

- 模型：K3，实际请求和返回均为 `k3`。用户提供的 `kimi-k3` 不在该 Coding 账号返回的模型清单中；使用返回清单中的明确模型 ID，没有错误后自动换模型。
- 接口：`https://api.kimi.com/coding/v1`，reasoning_effort=high。
- 输入：共享职责与判定 prompt，加每题 ID 和完整已导出的用户 turns；不把未导出的助手回复或历史当作确定不存在。
- 输出：50 个唯一 ID 全部返回，50 条不确定、0 条确定不可测；没有缺项默认放行。
- 批量耗时：50.929 秒；输入 2524 token，输出 2860 token（包含推理），合计 5384 token。连通探针另计，未估算费用。

## 检查及含义

当前助手逐题检查了 50 条 query 与理由，未见明确不可同时满足的原目标，也没有发现模型把不可见的源断言为空。客户保单、产品条款、机构指标等依赖均保留待确认；开放话术任务也未被强制标为可测。这是单次助手复核，不是独立人工金标，不能报告真实题准确率。

本次验证了 50 题一批的调用与结果完整性，在本批没有观察到凭不可见信息误排除。但没有真实的确定不可测样本作为参照，无法判断这层筛选的召回能力，也没有验证 50 题与更小批量的质量差异。

理由中的信息源归属有时仍是“客户/经营”“产品/权益”这样的粗分类；两条概念解释提到通用知识，但未据此断言实际源内容。这些理由可供查看，不能直接当作经过验证的依赖图。

信息源职责使用实验性的类别说明，尚非实际部署的完整供给审计。prompt 明确禁止以未列出某类源推断系统没有供给。因此，这轮测试的是无源内容时的保守标注，不能声称验证了生产环境的源内缺失判定。

## 补充边界诊断（看到全不确定后追加）

为区分合理的不确定与机械地输出同一标签，另准备 8 条合成题；预期结论在该次调用前保存，但不是与真实批次一起预注册的对照。使用完全相同的 prompt 和模型，独立请求，未提供预期标签。合成题不混入真实 50 题统计。

两条原目标要求同一对象同时满足不相容条件，预期确定不可测；六条对照覆盖源内容不可见、附件未展示、自包含改写、要求分析矛盾、不同对象分别计数，预期均为不确定。

实际返回 2 条确定不可测、6 条不确定，与 8 条预期逐项一致；识别到了明确矛盾，也没有把“分析矛盾”的任务误当成“必须满足矛盾条件”。这些是容易核查的人工构造例子，只能排除“本次模型对任何输入都一律不确定”的解释，不能证明真实业务题的识别能力或批量稳定性。

## 后续使用建议

现有形式足以继续作为起始条件列；本批的实际排除收益为零。若目标是筛出更多不可测题，需要提供能证明阻断的源证据或明确环境限制，不能靠提高模型“敢判”的程度解决。发现源内缺失前，不建议把信息依赖本身改成排除规则。
