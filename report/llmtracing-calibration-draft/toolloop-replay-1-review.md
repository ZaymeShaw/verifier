# llmtracing ToolLoop：首次真实冻结重放复核

## 范围与结果

已授权的一条完整冻结 A/B llmtracing 轨迹，仅运行一次；不调用 Insurance，不采集在线日志，不自动重跑。

结果：`toolloop-replay-1/result.json`。输入、源码快照/哈希、模型请求与返回、metrics、日志及进程退出状态均在同目录。原始材料含业务数据，仅用于本地审核。

- 整案耗时：247.0秒。
- 过程 loop：184.833秒，9次模型请求、12次工具操作、1个 segment。
- 主裁决：另1次模型请求；合计10次记录。
- 六轴全部执行成功；最终 not_fulfilled。
- context_memory / intent_understanding / planning_routing = sound；knowledge_data / model_capability / tool_execution = problematic。
- 两次 evidence_read，三次 call_inputs，七次轴提交（其中一次被拒、一次修正重交）。
- 没有触发提前结束后的 Stop 继续：segments=1。这次验证的是工具拒绝反馈，不是 Stop hook 的真实模型行为。
- 运行前后参与文件哈希一致。记录的端点模型为 gemini-3.8-flash-medium，不能视作实际服务端模型的独立认证。

## 确实观察到的自主行为

1. 模型先批量读取原文。
2. 随后自行查询三次调用的实际输入成员，并补读剩余原文。
3. 第一批提交中，意图轴把 `agno` 当作证据编号，提交被拒。
4. 下一次请求中，模型删除这个非法引用并重新提交，获得 accepted=true。
5. 其余轴陆续提交，全部被接受后模型结束；主裁决随后运行。

证据：result 中首个过程轴 `output.view.loop_calls`；请求与工具返回在 `call-003.json`、`call-004.json` 等文件。这里没有强制脚本模型的预设行为，是真实模型的工具选择与纠错。

这证明 ToolLoop 的读取、拒绝反馈、修正提交已经可用。但拒绝发生在非法编号上，不能扩张为“模型已经会修正证据不足的主张”。

## 校准结果

### 保住的正确判断

- 正确理解对象与性别/出生年月两个字段。
- 正确认可先搜索定位、再补查的顺序。
- 认可失败后保留已知性别、披露出生年月缺口，不要求整轮统一报错。
- 检出最终输出的过程文字与代码块混杂。
- 不再误称缺少真实 HTTP 实收。
- 模型轴本次逐调用引用通过实际输入归属检查，没有此前跨调用共用全部 source_refs 的情况。

### 未解决的关键问题：传递无损校验不完整

context_memory / arrives_intact 仍为 pass，断言工具结果无损到达模型。实际提交：

- input_refs：`t1.c2.m4`、`t1.c3.m6`（模型收到的工具结果消息）；
- output_refs：`t1.c2.response`、`t1.c3.response`（模型随后生成的响应）。

这两端可用于评估模型是否忠实处理收到的信息，不能证明业务工具原始产出到模型输入之间无损。

当前 `TranscriptEvidence.validate` 只在 output_refs 指向 `model_received_tool_result` 时阻断缺少原始工具产出的证明；本次换成模型响应，检查没有命中。用本次真实提交离线再次调用 validate，返回空问题列表，复现放行。

**这是本次提交检查实现的缺口，不是 ToolLoop 没执行检查，也没有证据证明模型在故意规避。** 它只需提出另一种不正确的证据配对，现有检查就可能接受。下次应校验该义务所声称的完整边界与两端角色，而非只命中一种错误输出端。

### 其余仍存在的推理问题

- planning / branch_condition：仍写“流程中无独立的条件节点、显式路由器或循环控制步骤”，不可见被说成不存在。
- planning / repeat_justified：未重复调用的事实本身正确，但只引用系统规则，不引用实际调用序列；合法引用编号不等于支持该事实。
- knowledge / data_per_subquestion：把统一失败消息进一步归成“服务不可用”；具体失败机制仍未定位，不应固定为服务可用性故障。
- 主轴 downstream_impact：仍写“终端用户直接看到了机器思维链推导过程及未解析的 JSON 代码片段”。只有 API 响应证据，没有 UI 展示证据。
- 多个位置仍重复引用同一事件，不能把展开后的条数当独立问题数或独立样本数。

## 用量：记录保留，暂不用于宣称省钱

客户端报告字段合计：input_tokens=543449、output_tokens=9744、reasoning_tokens=46373、total_tokens=599566、cache_read/write=0。

但存在明显需要核实的用量波动：call-004 的记录请求约45088字符，报告171260输入token；call-005 请求约47189字符，报告32935输入token。call-006 同样有较大跳变。最新 assistant message metrics 与整次 result metrics 相同，不能简单归因为本脚本重复求和；也没有独立上游账单或原始usage核验，因此暂不把599566作为已核实计费token，不估算美元费用，不声称比旧路线便宜。

247秒是一次实测整案耗时，不是稳定性能优势的证据。不同重放的推理深度、端点负载、缓存与轨迹长度均可能影响结果。

## 结论与下一步

**ToolLoop 的自主取证与反馈纠错路径真实跑通；证据语义校验尚未验收。** 六轴成功和最终标签一致不能代替引用支持性验证。

下一步只针对已复现机制补强：给 arrives_intact 的提交核对真实传递边界，两端不能用模型“处理后的响应”替代到达端。用本次真实提交新增离线回归，同时保留真正有两端证据的通过例与明确缺证的通过例，避免一刀切全判缺证。

主轴的自由文本影响与因果主张仍是独立待解决问题。本次授权的单次运行已结束，没有继续调用模型或修改生产实现。
