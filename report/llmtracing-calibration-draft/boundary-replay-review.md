## 复核结果

- F01 实收误认：两次不再声称缺少 API 调用方实收。R1 delivered_intact=pass，R2=fail；已纠正证据角色，但不是交付义务判定稳定的证明。
- P05 混杂内容：两次仍能发现。N01–N04 的正确理解、补查、保留已知事实、停止禁重试行为没有被整体翻成错误。
- F02 影响越界：仍存在。R1 主轴 downstream_impact 声称向终端用户暴露内部提示词/工具实现；证据只显示 API answer 中的过程文字，不证明提示词/实现本体泄露或 UI 已展示。R2 仍把未解析内容“暴露给用户”写成事实。
- F03 内部机制归因：R2 context_memory/delivered_intact 声称“桥接层未解析模型输出的 JSON 结构”，主轴照收并写“桥接层解析失败”。当前 llmtracing 证据不能证明这个内部机制。
- F04 单侧无损：两次 arrives_intact 都把工具调用请求作为传递前端、模型收到的 tool 消息作为后端，仍判“无损”。新增边界没有阻止。
- F05 不可见/未发生：两次 branch_condition 仍判 not_applicable，并断言没有独立控制节点或该情形不存在，而非限定可见片段。
- F06 引用分组：R1 arrives_intact 仍给两个位置复制同一组输入输出；R2 拆成单条，但输入端仍是错误证据类型。拆分格式不能代替边界语义正确。
- P06 条件项：R2 将顶层 gaps 泛化直接作为“澄清限制丢失”证据，未充分考虑 answer 中仍有具体缺口、字段契约未确认。不能据此将该项变成已验证 gold。

这些是同一轨迹上的人工复核，不是总体准确率。两次最终标签一致，不能掩盖 context_memory 一次 sound、一次 problematic，以及支撑理由仍越界的事实。

## 结论与下一步（未实施）

**这次提示词修正只局部有效，不足以作为证据边界问题已解决的验收。** 保留变更与两次结果，避免反复花钱试措辞或挑选看起来正确的一次。

下一步优先补最小的可定位证据结构，而不是增加第三个 judge：

1. 明确条目来源/角色和每次调用的实际输入成员，区分 tool_request、模型收到的 tool_result、真实 HTTP response、重建 output。
2. 用程序标记引用类型不匹配（例如用工具请求证明工具产出保真）、跨调用输入引用及无独立前端的传递证明；不直接把所有标记变成业务 fail。
3. 主轴必须处理未核验的证据主张，不能只接收一个已聚合的 sound/problematic 再自行补因果故事。
4. 保持 llmtracing 独立路线，不复建 Agno 环节枚举；先覆盖当前已复现的证据边界，再申请新的少量付费复验。

本轮批准的两次重放已全部用完，没有继续执行模型试验。
