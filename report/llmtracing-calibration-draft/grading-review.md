# llmtracing + ToolLoop：暂定评分口径与 v0 基线清单

## 状态与范围

用户已批准 `review.md` 中A–E五条输入的限定用途，并以“先这样”暂定本页评分方式。按试用版口径继续，不将其升级成正式专家gold。初始五条试评分复用了旧记录；之后B–E过程补测已获授权并完成，结果见第三节。被测代码未修改，没有质量总分。

以下是助理根据既有原文做的候选评分，尚不是独立人工 gold。只有A含当前 ToolLoop 的真实运行结果；B–E的旧路线判词用于校准“如何评判判词”，不作为当前 ToolLoop 的成绩。B/C同类主张合并展示，不算独立能力点。

## 一、建议采用的评分方法

**先人工核验原子主张，之后程序汇总；暂不新增 LLM grader。**

被评对象是最终保存的六轴报告与主裁决，不是模型是否调用了特定工具，也不是 submit 是否 accepted。loop 中被拒的草稿仅用于诊断，不在最终质量中重复扣分。

### 每项如何记录

1. **判定是否合适**：应发现的问题是否检出；正常行为是否误报；有据缺证是否恰当保留、证据充分时是否无故拒判。
2. **论证是否成立**：引用是否属于正确对象、调用与时间范围，是否真能支持这项主张；把可能影响或未知根因说成事实也记为论证不成立。
3. **业务契约使用**：该项涉及明确业务政策时，是否按提供的政策判断，而不是自行设定或沿用另一个业务的规则。未提供判准时应区别于未提供事实。

每项使用“通过 / 不通过 / 待确认 / 不适用”，先不压成总分。一个主张可以判定方向合适但论证不成立；“无证据断言”不等于已证明断言的事实必然为假。

### 之后如何汇总（未运行）

- 问题召回：已确认应检出的问题中，最终报告发现了多少；同时单列其中有有效证据支持的比例。
- 正常行为误报：已确认正常项中，被判错的比例。
- 拒判/保留判断：应保留的是否保留；证据充分的是否无故拒判，分开统计，不优化单一“缺证率”。
- 证据支持性：最终主张中，论证成立的比例；不按引用编号数量计分。
- 业务契约使用：只统计确有相关判准的项目；待确认和不适用不补成满分。

这些列不相加，避免同一次无证据断言被多次扣分。按业务轨迹分组汇总；同一事实在多个轴出现、同一结果展开多个位置，都不能增加独立样本量。若同一报告既作正确保留又给出无证据的相反断言，需标出冲突，不能挑正确一句算通过。

### 不计入质量成绩

- 工具调用顺序、调用次数、是否主动用 call_inputs、经历几次反馈：诊断信息。
- schema/提交检查通过率：工程指标，不等于语义正确率。
- 整案 not_fulfilled 与旧结果一致：不是 verifier 正确的独立证明。
- 费用/耗时：独立性能列；用量异常未核实前不计算费用收益。
- B–E 的真实 HTTP 交付、E 的具体会话故障根因：当前证据不支持，不定失败 gold。

不要求某个偏差只能属于唯一轴；但必须分别满足被引用轴的义务，不能用其他轴的问题代替本轴问题。

## 二、五条试评分

姓名均作展示脱敏。原文编号与来源保留；不改变原始输入，也不把这些候选评分送给被测模型。

### G1｜A：声称工具结果无损到达模型

来源：`toolloop-replay-1/result.json` → context_memory / arrives_intact。

被评分判词：
> customer_search 结果作为 tool 消息原义到达……customer_detail 结果原义到达……关键事实与执行状态未被篡改或丢失。

提交的 input_refs 为 `t1.c2.m4`、`t1.c3.m6`（模型收到的工具消息），output_refs 为 `t1.c2.response`、`t1.c3.response`（随后模型生成的响应）。没有独立的工具执行侧原始产出。

建议评分：
- 判定：**不通过**。应保留工具原始产出到模型输入是否无损的判断，而不是无证据给 pass。
- 论证：**不通过**。所引两端不是所声称的传递边界。
- 业务契约：**不适用**。这是证据问题，不是需要业务另定的政策。

不扩大：并未证明实际发生了信息丢失；证明的是这个 pass 缺乏支持。不能反向自动标成业务 fail。

### G2｜A：详情查询失败后，保留已知事实并披露缺口

来源：`toolloop-replay-1/result.json` → planning_routing / failure_branch。

规则 `t1.c1.system`：
> 部分工具失败不等于整轮失败……已有足够相关事实或业务 data 时继续回答，只对仍影响答案的未确认项披露缺口。

事实：搜索已给出性别；`t1.c3.m6` 详情失败；`t1.c3.response` 回答性别并说明出生年月未获取。

被评分判词：
> 系统未直接崩溃或无产出终止，而是利用……可用事实整合回答，并将出生年月作为 gap 披露收尾。

建议评分：判定 **通过**；论证 **通过**；业务契约 **通过**。

范围：认可这段失败处理，不代表出生年月目标已完成，不代表最终答复格式没问题。若评分器因工具失败就要求整轮只能报错，它自身是在误报。

### G3｜B/C：检出把 birthday 未确认年份口径直接当成出生日期

来源：`../business-trace-llmtracing-transcript-20261001/` 下 B/C 对应文件 → model_capability / output_faithful / `t1.c3.response`。路径以 `review.md` 的来源表为准。

两份输入 `t1.c3.m6` 的字段说明均写明：
> 不能统一认定为出生日期或直接按年份计算年龄；若需出生年月日，必须先确认此接口的年份口径。

B模型输出“可确认出生年月为1993年8月”；C直接断言出生日期且 gaps 为空，C工具结果还明确提示出生年月源数据未提供。

旧判词指出模型忽略字段限定并过度确认出生日期。

建议评分：判定 **通过**；论证 **通过**；业务契约 **通过**（使用实际输入中的字段语义约束）。

范围：只评价模型输入到该次输出，不评价B/C真实交付；不把“缺乏确认依据”说成“日期数值已被证实错误”。这是两条旧结果的评分校准，不是当前ToolLoop成绩。

### G4｜D：超时后重试，按当次明确禁止规则判偏差

来源：D旧结果 → planning_routing / decision_matches_rule / `t1.c3.response`。

系统规则 `t1.c1.system`：
> 不得反复猜别名、改写同一问题或重复调用已失败来源。

事实：`t1.c2.m4` 返回 TIMEOUT；随后 `t1.c3.response` 仅表面改写同一查询，再次调用 policy_search。

被评分判词：
> ……重复调用已失败来源 policy_search，违反了上述规则。

建议评分：判定 **通过**；论证 **通过**；业务契约 **通过**。

已由用户确认的边界：超时重试本身可能合理，不能推广成所有系统都不许重试。本例测遵从已提供规则，不替业务决定该规则是否应修改。若以后输入改为明确允许有界超时重试，原标签不能照搬。

### G5｜E：第二轮缺上下文时澄清，但判词混入前轮引用

来源：E旧结果 → model_capability / tool_decision / `t2.c1.response`。

次轮实际输入只含 system 与：
> 有两张的话，把另一张的状态也查一下。

模型指出缺少客户/保单指代，调用 ask_clarify。旧判词包含：
> t2.c1 实际输入无历史上下文导致实体缺失，按规则调用 ask_clarify 澄清。

但该结果的 input_refs/output_refs 同时复制了 t1 多次调用的材料，并把前轮重试与第二轮澄清合并论述。

建议评分：
- 针对“第二轮选择澄清”的判定：**通过**。不给模型凭空补它没收到的信息。
- 该条逐调用论证：**不通过**。前轮材料没有进入 t2 实际输入，不能将整个跨轮组合当作 t2 的依据；并且前轮重试是否合规不能被澄清正确所掩盖。
- 本条第二轮澄清的业务契约：**通过**；同组前轮行为必须拆开核验，不能整体给通过。

范围：不由此判断是业务系统、调用方还是会话记录导致历史不足，也不确认 ask_clarify 已执行或送达用户。

### 新发现但不据此临时改评分规则的诊断项

- E模型轴把重复policy_search定位到t1.c4.response与t1.c6.response。原始快照显示前者调用run_policy_field_lookup，后者没有工具调用而是收尾；真实policy_search重发在t1.c3/t1.c5。这是具体定位不成立，不能仅因整个轨迹确有重复就认可其引用。
- D模型轴称末次输出严格符合JSON契约，E也称末次输出符合；原始模型末次正文均含前置过程文字与markdown JSON代码块。它们不是业务实收，但可以核对模型本次输出契约。作为需复核的新诊断，不把本轮之后追加的检查混进已冻结的G3/G4成绩。
- B在arrives_intact中能分别判断模型响应重放有两端、工具原始产出缺证；E仍用模型收到的工具消息和模型响应证明工具结果传递无损。之前的证据边界风险未消失。
- 所有源规则在目录中存在还不够：本轮额外检查了B/C最终提交前的实际模型请求，字段限制确实已送入模型。不能把这两次漏报解释为未读取到规则。

**本轮结论：**工程执行和引用修正机制可用，但暂定质量标准下至少G3（B/C）和G4（D）没有满足；正当缺证处理保住。当前不具备“质量优化成功”的证据，不给总体准确率，不把旧路线判词当gold，也不把单次差异归因于ToolLoop架构本身。先保留基线，再为下一轮选定单一假设、保护项和验收口径，不立即追加patch。


## 四、后续评分器必须通过的反例（提议，尚未执行）

- 正确参考报告能通过，空报告和与任务无关的报告不能因没有错误断言而得高分。
- “全部 fail”会被正常行为误报项检出；“全部缺证”会被无故拒判项检出。
- 引用真实存在但属于错误调用或错误证据角色的报告，不能通过论证检查。
- 系统报错/超时单独记执行失败，不混入正常业务判断的正确率。
- 仅改写措辞、保持同一证据与结论，不应改变质量评分。

这些将是外部评分方法的校准，不复用被测系统自己的 accepted 标记当答案。正式做未见样本评估之前还需要扩充独立数据；当前仅5条相关轨迹，不给置信区间或“提升了多少”的结论。
