# 重标任务：旧 Insurance 模型最终输出是否"能直接给用户看"

背景：旧 Insurance 交付给用户的文本是每一步过程叙述的拼接。现在假设交付层只交付模型最后一次输出，重新判断这段输出本身能不能直接给业务人员看。

材料：`in/<题号>.md`，每轮一段"模型最终输出"。只看这些文字，不需要判断内容对错。

每题输出一行 JSON：

```json
{"case":"A01","clean":true,"privacy":false,"has_answer":true,"reason":"一句话"}
```

- `clean`：所有轮次都满足才为 true。为 false 的情况：
  - 有成段的内部思考或自言自语："让我…""我需要先…""我应该…""Let me…""I should…""I need to…""I now have…""</think>"、英文推理段落、复述系统规则（"按指引我不能…"）；
  - 字段名堆砌（如 newClientType、agentNo 原样罗列）；
  - 停在"让我给出回答"之类、没有成形的答复。
  - 只有一句开场白（如"已查到，整理如下"）算 true。
- `privacy`：出现用户没要求的身份证号或手机号明文（脱敏的尾号不算）。
- `has_answer`：至少有一轮写出了面向用户的答复内容。某一轮是"（空）"或只有思考，在 reason 里写明是第几轮。
- 拿不准时 reason 里写"不确定：原因"。

写到 `out/<批次名>.jsonl`，只读 `in/`，不改其他文件。完成后只回复：批次名、行数、clean=false 的题号列表、最拿不准的 3 题。
