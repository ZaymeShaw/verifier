# axis loop（llm_probe_loop）与工作流路线（llm_probe）dev 对比（2026-10-21）

样本：`report/eval-main-axis` dev 43 条 × 3 次，同一份 gold、同一判分（兑现整体状态 vs gold）。holdout 未跑。
- 基线：`runs/axisloop-baseline`，工作流路线，代码与数据在隔离副本里跑（scratchpad/baseline-code，取自 verifier-integrate）。
- loop：`runs/axisloop-dev`，axis loop 路线（需求 → 说法 → 真实性 → 兑现 → 主轴结论），单独跑，与基线同为 6 并发、同一模型（gemini-3.8-flash-medium，primary）。中途断网停过一次，续跑。
- 两边各有 1 次运行失败，都不计入下表：基线是兑现轴两次输出都没过校验；loop 是被测业务代理那一侧连接错误（`streamed agent run failed: Connection error.`，环境类）。

## 耗时按场景

| 场景 | 次数 | 基线中位 | loop 中位 | 基线请求 | loop 请求 | loop 工具调用 |
|---|---|---|---|---|---|---|
| hr-handbook-qa（ES） | 33 | 81s | 141s | 10.8 | 16.9 | 18.1 |
| policy-clause-qa（ES） | 15 | 144s | 197s | 13.0 | 18.9 | 21.1 |
| verify-insurance-mcp（MCP） | 79 | 360s | 492s | 25.7 | 25.1 | 55.1 |

待查证的原因（还没逐条核实，是推测）：
1. **ES 场景多了约 6 次请求**：编排开销——需求轴主任务调子 loop 再收尾（+2）、每个任务的收尾提交各一轮、判 blocking 的子 loop（基线也有一次 blocking 调用）。
2. **ES 每次检索都新拉起一个 MCP server 进程**（基线直连）：ES 场景工具调用约 18–21 次，每次约 1 秒启动。
3. **保险场景请求数持平但慢 130 秒**：工具调用 55 次（含提交）；loop 是串行的一条主线，基线的核事实按条判，查证与判定分开、每步上下文短；loop 主上下文随任务累积变长，单次请求更慢。

## token

两边结果里都没记 token。每次请求的 token 在上下文记录里（`response.metrics`），但项目只保留最近 500 条，基线早期 case 已被清掉。要补测需临时调大保留上限、两边各跑 1 轮 dev，按 trace 汇总。

## 结论（暂定）

准确率、误放行、重跑稳定性三条硬门槛都过了，且 loop 在稳定性上略好；耗时没过（约 2 倍），token 未测。下一步先查清耗时的来源再决定改什么，不在这一步调规则。

## 补充：断网恢复后遇到端点重试的运行重跑（2026-10-21）

原 loop 结果里 16 次运行有端点失败重试（主端点 `Connection error`，两个备用端点额度用完 / 余额不足），另 1 次因连接错误失败。这 17 次重跑进 `runs/axisloop-dev-retry`，16 次无重试、1 次有 1 次重试，结论全部不变（原来对的仍对，C08 那次两边都错）。

| | 这 17 次的耗时中位 |
|---|---|
| 原 loop（有重试） | 745s |
| 重跑（无重试） | 663s |
| 基线 | 413s |

替换后整体（128 次）：一致 116 vs 基线 115，误放行 9/65 vs 9/65，耗时中位 325s vs 169s，请求均值 22.4 vs 20.4。

结论：端点故障只解释了一小部分（这批中位 745→663s），去掉之后 loop 仍约 1.6–2 倍于基线。方案本身的两处开销：
1. **固定编排开销**：简单 case 也要走完需求子 loop、各任务收尾、blocking 子 loop。`mcp-smoke-neg-unknown-policy` 基线 4 次请求 28s，loop 14–15 次请求约 200s。
2. **单次请求更慢**：大 case 上 loop 的请求数反而比基线少（如 F01 22 vs 32、C08 25 vs 42），却更慢——主上下文被取证案卷撑大（占 80%），每步都带着它。

## R8：重构后（2026-10-22）

重构内容见 `spec/implementation/axis_loop.md` §8：需求、blocking、真实性改为独立运行（主 loop 看不到其过程），需求按轮分发，真实性调公共 loop 工具 `search_knowledge` 取证；另修了逐字引文校验对 JSON 转义的误判（会逼模型反复重查）。
