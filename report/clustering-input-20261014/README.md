# 聚类输入对照（2026-10-14）

数据：候选区 32 题（c7a504df + f763d7da）六个过程轴，共 192 个 case×轴。聚类标准、提示词与线上一致，只换送进聚类的记录。只读 latest_runs，不写库。

## 现行输入漏了什么（gap_stats.py）
- 过程轴只送问题记录（problem → issue）；问题只能由"没达到"或"意外"生成。
- 没有进聚类的：
  - 103 个没有问题记录的轴：正常 66 个，无法评估 37 个；
  - 9 个判定失败的轴；
  - 372 条无法核条目，任何情况下都不进。
- 121 条没达到条目全部经问题记录进入聚类，没有漏。

## 结论（同一模型）
- B 局部变差，这个结论在同一模型下仍然成立：
  - 45 条记录要拆进多类；
  - 规划轴的 problematic 标签下出现"编排路径合理但交付或记录缺失致无法核对"，意图轴 D01 的归属和排序两个问题被并成一条；
  - "需要追问未调用 ask_user""违反别给合计数"等具体问题被并进大类。
- C、D 在规划、工具、知识轴上和 A 一样细；另外看得到无法评估的原因和评测器失败。
- 模型能力轴 D 只分了 5 类（把过程话、内部词、Markdown、例行注并成一类），比 A 的 11 类、C 的 8 类粗。但 A 自己三次的类数是 9 / 8 / 11，这一点要多跑几次才能分清是方案差异还是正常波动。
