# 案卷整理改为 LLM 轮次预算

## 触发与批准范围

8021 批次 72165a6d635c4c46900a9288b6daa594 的 customer-profile-fuyunping 用例，案卷整理第 5 次模型回复提交结果，但此前有 12 次取证工具调用，第 13 个工具 submit_structure 被预算中止；提交尚未进入验收。这是评测器阻断，不是业务违约结论。

用户批准：案卷最多 8 轮 LLM 调用，取消案卷 12 次工具限制，反馈剩余轮次，提交验收通过即结束。六轴共享评测预算另行讨论。本次未重启服务、停止批次或发起真实模型/业务评测。

## 实现

- ToolLoop 的 History 与 LoopResult 记录 llm_calls；每次 complete_step 前计一轮，多个同批工具仍为一轮。客户端内部的端点重试不重复扣轮次，仍由原客户端记录请求尝试。
- BudgetStop 增加 llm_calls；只在新模型请求前检查轮次，保留可选工具次数与墙钟限制。使用了最后一轮仍执行该回复的全部工具及提交；若完成检查通过，直接提取结果；未完成时不请求下一轮。
- 案卷轴及共享 Analysis 使用同一 8 轮常量，工具次数不限，保留 7200 秒协作式墙钟及既有读取体积上限。轴声明、运行预算及结果 usage.limits 一致。
- 每次模型请求前反馈已使用和剩余轮次（包含本轮）；提示词鼓励同轮批量取证、利用已有正文、及时提交并留出修正机会。
- StructureCompleted 复用已有 ready_to_finish；accepted 后仍经过所有 stop 检查和 end 提取，不能绕过辅助验收。证据回执规则未放宽；同批读取与提交仍被拒，必须下一轮引用。
- 父子循环分别计数；复用同一实例的下一次 run 从零计数。案卷 usage 来自框架计数，不另开影子循环。
- 实验台原观察器也包装 budget，本次同步透传 before_step、step_note 及 ready_to_finish，保证观察模式不改变执行语义。案卷实现指纹纳入真正的 runtime/hooks/types 文件。
