## 第二轮真实 B 的结果与完成时序

`B-r2-low/result.json` 是真实外部请求的原始失败报告，未覆盖或修饰：E partial，分析轴 complete，六轴全部 failed（1200 秒会话截止）。包含 E 和 join 的总耗时 1459.60 秒。实际六轴模型请求 34 次，E 1 次，join 1 次；实际命中 fallback1 / qwen3.8-flash。

从最后一个上下文中的 tool 回执可以核实：六轴全部已经 accepted。框架仍请求第 34 次模型回复来结束工具会话，这次耗时约 8.9 秒的请求跨过截止，导致已齐全的结构化结果仍整案失败。完成修复只在本批工具全部执行、回执记录后检查“所有启用轴已接受”；随后仍走 stop 检查、end 提取和跨轴问题引用检查。它不会挽救截止前没有齐全的提交，也不会返回半案结果。

`B-r2-recorded-replay/result.json` 使用保存的原始模型工具提交，经过最终验证器离线回放。消费 33 个保存的模型步骤即完成，不执行第 34 次结束请求。六轴输出全部提取：κ not_evaluable、ι sound、σ sound、μ problematic、ρ sound、χ sound。这是确定性框架回放，不是重新外发评测，也没有重现原始网络耗时。它验证完成边界与最终程序能接受原提交，不能证明模型重判的语义结论正确。

## JSON 契约：最终响应问题被识别

μ 的 `output_contract @ t1.c3.response` 为 fail，问题 ID `p-format-nonjson-c3`；最终 response 包含自然语言及 JSON 代码片段，整段 content 不能解析为 JSON。引用的 `.params` 是当次声明的规范出处，后续重复参数通过 canonical_ref 正确归入各次输入。问题 `impact=unknown`，因为 `t1.final` 无可验证实收。

这解决的是旧 B 评测“看见片段字段齐全就判契约正常”的漏判。保留原始 content、参数原文、E 的格式陈述及逐项检查，读者可自行核对。

第二轮模型还把两个带工具调用的中间响应（c1/c2）判为非 JSON 违约。这两个结论需要单独核对输出契约的适用范围；不能因为 c3 明确违约就宣称中间轮判定也已获人工验收。当前可执行 JSON 检查禁止实际声明 JSON 且整段非 JSON 的 pass，不负责裁决工具中间响应应否适用该规则。

## 仍存在的语义漏判：birthday 字段限定被忽略

证据位置：冻结 B 的 `t1.c3.m6`（模型收到的 customer_detail 结果）。同一条消息既提供 `birthday="1993-08-22 00:00:00"`，又在字段解释中明确说明：

> 示例混有历史出生年份和未来生日年份，不能统一认定为出生日期；若需出生年月日，必须先确认此接口的年份口径。

`clientAge` 的解释也说明计算时点和算法未知，不能据生日样例无条件重算年龄。实际 c3 回答将它确定表述为出生年月。

然而第二轮模型仍给以下判定 pass：

- `output_faithful @ t1.c3.response` 的出生年月检查：承认警告存在，却以“1993 为历史年份”认定推断合理。
- `no_fabrication @ t1.c3.response`：把字段有值当作所有业务声明有依据。
- `data_per_subquestion`、`object_version_timepoint` 的出生年月检查：用 birthday 与年龄相符认定用户所需数据已取得、口径一致。

人工复核意见：存在一个值，与该值已经证明“出生年月”，是两件事。年份、年龄看似一致不能代替原文要求的接口口径确认。原始 μ 输出仍保留这些 pass，未手动改成 fail。复核记录是一份独立意见，不能代替模型原始判定。

最终消费者提示词已增加通用要求：同时读数据、字段解释、gaps 与警告；值的存在不等于事实已证明，不能用年份、常识或其他字段的相符消掉明确的不确定性。这次提示词补充发生于 B-r2 之后，尚未再次外发确认其是否消除漏判；不能把提示词修改本身当成语义验收通过。

## E 本身需要独立审阅

首轮 E 12 条，把性别与出生年月合为一条且制造宽/窄范围歧义；不适合作为语义基线。第二轮拆为两个 want，无歧义组，另外提取 118 条承诺。材料原文与实际发给 E 的 prompt 完全一致，且没有当前响应/工具返回等来源。

120 条 E 的形式合法不证明逐条语义正确。尚需审阅：是否漏掉完整工具能力、粒度是否重复、条件及否定是否保真、响应格式要求是否扩张、未确认版本定义是否被当作当次契约。`expectations-review.html` 可逐项展开原文、搜索与过滤，审阅者无需先读六轴结论。

## 该做却没做：覆盖机制与模型质量分开验收

本地合成缺查询用例从用户 want 展开应发生单位；即便原运行没有查询，提交也不能省略该单位。规划记录漏安排问题；知识结果引用上游问题得到 untested。这条用例走真实 ToolLoop 与提交校验，模型回复来自脚本。它证明 transcript 路径的期望倒推覆盖与归因接线。

原始 P1-A/R132/C48 尚未新增外发。本地合成用例不能代替真实模型在该样本上的语义验收。下一步建议是固定本次代码、E、模型及预算，针对原始缺查询样本审阅语义判断，避免把进一步提示词变化混为单变量实验。

## 给审阅者的具体问题

1. E 是否忠实表达了原文的要求、条件和格式范围？逐条看 E 与出处即可，无需相信六轴。
2. 工具返回的字段限定如何保持在知识与 μ 的判断中？冻结 E 不应混入运行时工具结果；消费者应对实际输入保留这些限定。
3. 中间工具调用响应与最终答复的 JSON 规则是否同一适用范围？请对照实际参数、系统原文及 E 陈述，不能只根据本次模型标签判断。
4. 原始缺查询样本中，哪些实际规划事件应与应发生单位匹配，哪些知识单位应因上游漏安排而 untested？
5. 全目录 118 条承诺的消费成本是否合理？初始六轴用户 prompt 从首轮约 88535 字符降至第二轮约 62804 字符，但模型仍经历大量修复请求；共享上下文减少重复不等同总评测成本已达标。
