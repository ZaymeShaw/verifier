# 过程六轴：模型输出的抽象（草案，待确认）

依据 `demand/process_axes.md`。只回答一件事：六轴评测时，**哪些信息只有模型能给**。格式与实现另议。

## 1. 用的人需要什么

| 需求 | 需要的信息 |
|---|---|
| §2.1 看整体 | 每轴 verdict + 组成，能下钻到具体问题 |
| §2.2 看单个 case | 每个问题：哪一步、什么现象、预期、实际、可回查的 trace 引用；该做没做也要记 |
| §2.4 看评测器自己 | 每个结论能追到依据的判准和事实 |
| §4 归属口径 | 单位取六值之一；输入无效必须指向上游问题；定位不了列候选轴 |

## 2. 程序负责（模型不写）

- 有哪些单位（子能力 × 行使，含应发生单位）
- 每个单位挂哪些判准，判准的预期原文与出处
- 每个单位的证据端点；交付了哪些材料
- 单位最终取值（按 fail > 缺证 > 做到 > 输入无效 > 未发生 汇总逐条结论）
- 轴 verdict 与组成

## 3. 模型负责（只写判断）

**轴级**
- reason：这个轴看到了什么、结论为什么是这样（必填）
- scope_note：一两句话说明检查范围和看不到的部分

**每个单位**
- 对挂给它的**每条判准逐条**给出：结论（六值之一）＋ 看到的事实
- 仅在需要时：
  - 应发生单位 → 对接到了哪次实际行使，或没找到
  - 缺证 / 缺判准 → 缺什么
  - 输入无效 → 指向哪条上游问题

**每个问题**（一个独立问题一条）
- 现象：一句话
- 违反了哪条判准 → 事实**直接沿用该判准结论下写的事实**，不另写一份；预期由程序按判准补出
- 依据不在该单位自身输入/输出端时，指出依据在哪
- 归因：本轴，或"未定位"＋候选轴
- 对最终交付的影响：有 / 无 / 不明
- 涉及哪些单位

## 4. 不再让模型写的

单位的义务名与位置编号、判准编号的抄写、判准出处、每个单位"看了哪些证据"的引用及其门禁、预期原文、单位总结论。

## 5. 已确认的取舍

- 逐条给判准结论（看得出哪一条没做到，fail 不会被盖住）
- reason 必写，scope_note 简写
- 问题里的事实与判准结论下的事实统一为一份
- 去掉"单位看了哪些证据"的引用及对应门禁
- 不以下游聚类为前提
