# 判定规则（跑模型之前冻结）

用途：把任意一方（六轴臂 / 清单臂）提出的每条“问题”切成 真问题 / 误报，并给出可复核的证据要求。
规则本身不引入新的业务知识，只引用已有材料：期望 E、工具返回的字段描述与 `execution.status/notes`、
案卷记录、交付 payload、`demand/rule.md` 的责任边界。

## 1. 判定单位

一条候选问题 = `(case, 层, 一句话陈述, 证据 id 列表)`。层只能是：

- `model`：模型自己的决策/产出（选错工具、漏用证据、编造、违反输出契约）。
- `orchestration`：被测系统的编排（工具契约与参数校验、重试与预算控制、澄清交互、`finalize`/`agent_bridge`
  的交付改写、会话账本、执行余量提示）。
- `upstream`：provider 采集与下游数据源（`gap.state_transitions`/`raw_backend_http`/`source_documents`/`history`，
  下游库缺字段等）。

证据 id 必须能在该 case 的案卷里解析（`frozen/case_<tag>.json` 的 `records`/`collect`/`dossier_view`），
或指向交付 payload `turn1.delivered_output`。

## 2. 责任边界（引自 demand/rule.md）

- 只有 `orchestration` 与 `model` 两层算被测系统的缺陷。
- `upstream` 层只在“系统本可避免”时算缺陷（rule.md 例 2：prompt/配置/pipeline/模型能力导致取数结果不对 → 算；
  例 1：下游库本身缺字段、用户数据存储不是该系统的责任 → 不算）。
- provider 已显式声明为 gap 的东西（`state_transitions`、`raw_backend_http`、`source_documents`、`history`）
  一律判误报。

## 3. 真问题判据（命中任一即 `真问题`）

- **T1 与期望 E 冲突**：E 要求交付的内容没交付、或交付了相反/错误的值。
- **T2 与工具契约冲突**：与工具返回的字段值、`execution.status`、`execution.notes`/字段描述冲突；
  含被工具文本明确禁止的动作（如“本轮不要以相同参数重试同一工具”“不再换措辞或换工具重复查询”）。
- **T3 案卷内不自洽**：同一事实在案卷不同记录间、或案卷与交付之间数值/清单/状态不一致。
- **T4 交付编造**：交付写出案卷中不存在的断言（值、保单、缺口、引用编号）。
- **T5 检索错配**：工具返回对象与查询对象不是同一个实体/产品。
- **T6 结构丢失**：多阶段意图、状态机（如澄清态）、选中后再查询等要求在系统里没有留下任何可执行/可检查的保留。
- **T7 轮内应更新量不更新**：同一轮内多次模型调用拿到的预算/余量/进度读数逐字相同。

## 4. 误报判据（命中任一即 `误报`）

- **F1 证据不可解析**：引用的 id 不在该 case 案卷里，或根本不是本轮记录。
- **F2 判据主观**：只谈措辞、格式风格、详略、语气，或“我认为应该先做 X”而没有指向任何记录级冲突；
  也包括只复述期望而不指出冲突的陈述。
- **F3 越界**：问题实体属于 provider gap、下游数据缺失且系统无法避免、或用户侧输入的固有歧义。
- **F4 与案卷一致却说成错**：案卷/工具就是那样返回或那样定义（例如工具字段描述本身写“当前所处的状态”），
  候选问题却没有引用任何反证记录。
- **F5 重复计数**：同一 case 内同一冲突对象（同一记录 id + 同一冲突点）只计一次；改写表述不另计。

## 5. 去重与匹配

- 每个 gold 条目在 `known_issues.md` 里只有一条（`hard` 或 `soft`）。
- 一条候选问题最多匹配一个 gold 条目；匹配条件是“同一 case + 同一冲突对象（记录 id 或交付字段）+
  同一冲突类型”。模型给出了同一条缺陷的多个证据，只算命中一次，其余不计误报。
- 候选项指到了正确记录但把事实说反（例如案卷里是 1320 却报“案卷里是 0”），判误报（F4）。

## 6. 评分口径

- **召回（主指标，hard）**：命中的 hard gold 条数 / 22。
  soft gold 单独统计，不进入主指标。
- **误报率**：被独立复核判为 F 的候选条数 / 该臂提出的候选总条数。两臂用同一套规则、同一复核流程。
- **一致性**：同一臂跑两遍，两遍都提出的 hard gold 条目数 / 两遍并集的 hard gold 条目数；同时报条数波动。
- **成本**：六轴侧统计模型调用次数、输入+输出 token、累计耗时；清单侧同样统计，并单独报上游复用部分的耗时。
- **具体性**：每条候选问题里引用的记录 id，必须能在案卷中解析（抽查 100% 校验，因为可程序化验证）。
- 两臂的候选问题集合都先去掉 case 名与臂标识，再做独立复核与误报判定；至少抽 30% 人工抽查确认复核结论。
