## 1. 当前问题是什么

**建议先纠正分类对象，再谈枚举名称。** 当前的“六轴”混合职责与执行者；“五态”混合判断结果与未决原因；轴级单值又掩盖部分未判定；“两轴共担”将定位不明升级成两次确定失败。这些是不同问题，不能靠多加一个枚举值同时解决。

| 现状证据 | 可复核的问题 | 对抽象的影响 |
|---|---|---|
| `spec/math-abstract/process-axes.md:49–60` 把表达/编排/传递与模型调用列为同层类型；`adapters/model_capability.py:12` 又检查工具决策 | 模型能承担规划、表达和生成，分类条件并不正交 | 义务归职责，模型归执行者维度 |
| `business_trace/links.py:33` 后的 LIMITS 声明环节表不是全部环节；现行抽象用 S 选择环节后聚合 | 检查范围被遗漏时，已选范围的通过不能证明整轴健康 | 通过必须绑定范围及覆盖闭合依据 |
| `adapters/process_common.py:331` 先过滤 contract_missing，再 any_pass | pass + contract_missing 实际返回 sound；not_applicable + contract_missing 返回 not_applicable | 未决项不能在汇总前删除 |
| `spec/math-abstract/process-axes.md:83` 规定边界不见时两轴都记偏差 | “工具或数据源至少一侧错”不推出“两侧各自错” | 复合违反与局部责任分开 |
| `adapters/knowledge_data.py:10` 明确“查询未执行”也判数据缺失 fail | 这是没取得数据，不是数据源缺陷的充分证据 | 结果后果与局部义务不能互换 |
| `spec/math-abstract/process-axes.md:35` 平台不可见不产生看不清 | 可见性来源无法决定某条具体主张是否有证据 | 用“能否支持本题判断”判断缺证 |
| `adapters/process_common.py:297` 缺证的正面状态降级，fail 缺两端只加 flags | 结构可疑的失败仍可能进入 problematic | 两个方向的确定结论都须满足证据约束 |

上述 adapters 路径均相对于 `impl/projects/llm_probe/eval_axes/`。最后一项描述共享函数；当前 llmtracing 路径还有提交前回执与边界检查，不据此断言所有路径都能放过同一缺证结果。

另有协议自身冲突：9 月 29 日抽象允许独立义务多处失败，10 月 1 日方案又要求“只记首个出错环节”。后者应改为“不因同一错误的如实传递而重复归责”；若下游另有验证义务且也未履行，应保留其独立违约。根因数、失败义务数、受影响环节数不能共用一个计数口径。

反例复核方式：仅从当前源码 AST 取出 `aggregate_verdict` 原函数执行，不初始化项目、不调用模型或服务。它验证汇总语义，不声称验证整个端到端系统。

## 2. 为什么以“义务”为分类单元

一次模型调用可能同时理解用户、决定调用工具、编写答复。若强制给“调用”一个唯一轴，势必丢信息或重复；若检查的是“当时信息已充分却仍无依据重复调用”这条义务，它可以稳定归行动选择，不因执行者换成程序而换轴。

原子义务写成一句完整的话：**在什么范围和情形下，谁应当保持哪种关系，依据是什么。** 同一对象、同一范围、同一实质要求只记一次；不能通过换编号把一个要求复制成两条。原子化与同义要求合并仍需语义审核，数学记号本身不保证它已实现。

局部遵循与系统设计质量都可以检查，但必须用不同范围、不同判准明确区分：

- 模型按照当次提示词做了错误业务策略：局部遵循可满足；系统策略违反外部业务要求则另题失败。
- 不能因为提示词写了某条策略，就认为策略一定合理；也不能把模型没收到的要求拿来判它没遵循指令。

方法参考成熟的 Design by Contract：把适用条件与履行保证分开；这里额外处理“观察材料不足以判定”，是本项目的扩展，而非声称直接照搬 Eiffel。[Eiffel 官方说明](https://www.eiffel.org/doc/eiffel/ET-_Design_by_Contract_%28tm%29%2C_Assertions_and_Exceptions)

“未定”也不能自动当作 false；OPA 官方说明同样区分 undefined 与 false。这只支持两者需要区分，不表示采用 OPA 的默认聚合行为。[OPA 官方文档](https://www.openpolicyagent.org/docs)

## 3. 两条轴划分路线

| 路线 | 能解决什么 | 代价 |
|---|---|---|
| 保留六个现名，承认是重叠诊断视图 | 继续回答“模型做了什么、流程做了什么” | 不能宣称六轴是唯一归属分类；跨轴总量不能直接求和 |
| 六个职责类别 + 执行者标签（本稿推荐） | 同一义务不随模型/程序实现替换而换轴，支持跨项目比较 | 必须重定旧模板，模型视图改为跨职责筛选 |

**六不是数学必然。** 候选六类来自对现有义务的整理：意图表达、行动选择、操作执行、信息传递、数据供给、内容推导。把“模型能力”换成“内容推导”只有连同工具决策等义务一起重新归位才成立，单改名称没有效果。若用户真正需要模型固有能力结论，还需要控制输入与多次测量；单条执行轨迹只能证明本次表现。

“内容推导”和“信息传递”的边界以契约为准：要求已有事实原义到达，则是传递；要求基于已知事实计算、比较或作出新结论，则是推导。一个摘要步骤可能同时承担两种不同义务，不能仅凭“摘要”这个实现名字决定。

“操作执行”和“数据供给”的边界也以主张为准：前者检查指令有没有正确执行、请求响应及技术契约有没有守住；后者检查源事实能否按数据约定满足请求。看不到内部边界就不能凭一次空返回替双方各自定罪。其余无法归类的新要求保留明确的待归类项，不伪造六类的全宇宙完备性。

## 4. 用边界判例检验候选

以下是协议推演，非新一轮模型准确率测试。确定结论均以表内前提已有可靠证据为条件。

| 场景和已知前提 | 候选判定 | 禁止推出的结论 |
|---|---|---|
| 模型正确理解任务，却违反已收到的重试规则，同参重试 | 行动选择 fail；执行者=模型 | 不另复制一条“模型能力 fail” |
| 模型缺少本应由系统注入的历史；正确表明无法解析指代 | 信息传递 fail；意图表达按实际输入逐题判 | 不以事后全历史判它必然误解 |
| 指代所需历史已收到，仍绑定错对象 | 意图表达 fail；执行者可为模型或程序 | 不因使用了历史就归上下文 |
| 工具按正确参数操作，源数据本来应为空，返回空 | 适用的操作与数据义务可 pass | 空结果不自动 fail |
| 已证应存在且有效的数据不存在，操作执行正确 | 数据供给 fail | 不让工具再背同一缺数后果 |
| 应有结果却为空，证据只支持工具或数据侧有错 | 复合请求范围 fail，局部各侧未定 | 不把“或”变成两个 fail |
| 应调工具且前提满足，却没调用 | 行动选择 fail；缺失动作也进入问题集 | 数据未取得不证明源数据不存在 |
| 调用了工具但超时，时限与到达时间已证实 | 相应操作履行义务 fail；数据侧按自身适用性判 | 没看到源数据不等于源数据差 |
| 一次调用耗时 12 秒，找不到适用时限 | undetermined，原因=缺判准 | 不擅自定 10 秒阈值 |
| 模型输出正确，bridge 在纯转交时改成错误数值 | 信息传递 fail；原内容推导可 pass | 不把最终答案错倒灌给模型 |
| 程序正确传递两个数，模型算术结论错误 | 内容推导 fail；信息传递可 pass | 推导错误不因数值来自工具而归工具 |
| 规则不适用已有可靠证据，输出日志恰好缺失 | not_applicable | 不要求补齐与此题无关的所有材料 |
| 规则是否适用不明，或原规则存在未消解冲突 | undetermined，保留具体原因 | 不把“不知道适用”当“不适用” |
| 同轴一条 pass，另一条缺判准 | 轴摘要未定，已满足项仍保留 | 不汇总成 sound |
| 同轴一条有据 fail，另一条未定 | 轴摘要有偏差，未决缺口仍保留 | 不暗示“其余全部已查清” |
| 评测模型没响应、预算耗尽，未完成提交 | 评测运行失败/未完成 | 不伪装成被测系统自身不可评或违约 |

## 5. 与现行协议的关系

此稿明确提议改变三条现行协议，而非声称只是修实现：

1. 从“环节类型唯一归轴”改为“原子义务按职责归类，执行者另记”。
2. 从逐项五态改为四态 + 可并存的未决原因；轴级仍可用四个摘要，但重新定义聚合条件。
3. 从“未定位两侧共担失败”改为“保留复合范围失败，局部责任待查”。

不必为了得到数学感照搬 judge.md 的三态。judge、fulfilled、资料定位各自分类的对象不同；应借用的是“先固定问题和定义域，再证明值域互斥穷尽”的方法。

建议下一轮先围绕一个决策讨论：**六轴究竟要做互斥的职责分类，还是允许重叠的诊断视图？** 本稿选择前者；一旦选定，四态及其证据规则就能稳定下来。若选择后者，应接受模型与规划重叠，并明确统计不具有可加性。
