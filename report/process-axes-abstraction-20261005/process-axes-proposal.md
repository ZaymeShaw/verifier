# 过程判定：对象、职责与结果的数学抽象

> 讨论稿，2026-10-05。以下是协议修改建议，不是当前实现说明；六类是本项目候选分类，不宣称是所有系统的天然完备分类。现行协议仍见 `spec/math-abstract/process-axes.md`。判例与证据见同目录 `README.md`。

```text
运行现场 x，需求与规则材料 y
  ① 采集 T → 带可见性、时间、来源戳记的运行记录 R
  ② 定题 Q → 有界问题集 D：对象 × 原子义务；附职责类别与执行者
  ③ 核证 M → 每题的适用性 A、满足性 B、依据与未决原因
  ④ 内核 K → 满足 pass / 违反 fail / 不适用 not_applicable / 未定 undetermined
  ⑤ 汇总 Agg → 有偏差 / 未定 / 满足 / 不适用；保留范围与缺口
     ┆ 证据约束与覆盖检查：约束实参；未定位不推导两侧各自失败
```

## ① 采集：先定格“当时实际发生了什么”

`T : 运行现场 → R`。R 包括端点、时序、实际收到的输入和可见性；重建值携带验证限制。规则与需求材料 y 独立保留其版本、适用范围和权威依据。平台不可见和偶发缺失都只是来源属性：是否阻碍判断，取决于具体问题所需的证据。

## ② 定题：一个问题只检查一种关系

`Q : R × y → D`。D 是本次声明范围内的有限问题集；每题包含对象、原子义务、范围、职责类别与执行者。对象可以是已发生环节，也可以是有义务依据却未发生的动作；不能只枚举成功留下 trace 的动作。缺判准的候选问题仍保留，不能悄悄消失。

职责按**义务检查的关系**归类，执行者另作标签。同一次调用可以承担多条义务；同一原子义务在同一对象和范围内只登记一次。混合义务必须先拆开；归类不明保留待归类缺口，不强塞进六类。

| 候选职责 | 唯一要检查的关系 |
|---|---|
| 意图表达 | 当前可用的用户语义 → 内部任务含义是否一致 |
| 行动选择 | 任务、当时状态与规则 → 调什么、顺序、重试、停止是否恰当 |
| 操作执行 | 已选定的指令与技术契约 → 操作是否正确履行 |
| 信息传递 | 应传的既有信息 → 下游实收是否保留所需语义 |
| 数据供给 | 合法数据请求与数据约定 → 源事实是否存在、匹配、有效 |
| 内容推导 | 已获得的事实与规则 → 新结论、计算、答复是否有据且合规 |

模型、程序、外部服务是“谁执行”，均不直接决定职责类别。格式要求按其约束对象归类。纯转交属于传递；生成新结论属于推导。数据没拿到不能单凭后果判数据源错。

## ③ 核证：把判准与事实变成内核实参

`M : D中的一题 × R × y → 带依据的判断对 (A,B)`。

A 表示“本义务在本对象上是否适用”，B 表示“是否履行”；两者取值均为 `{是, 否, ?}`。`?` 表示尚不能得到单一结论。判准缺失或冲突时，不能给 B 确定值；适用性依赖的判准缺失时，A 也必须为 `?`。判准已知且有独立排除证据时，可直接确定 A=否，无需补齐无关输出。

确定值必须有可核验依据；相互冲突且未消解的证据只支持 `?`。未决原因记录缺判准、缺事实、适用性未明、证据冲突等，可同时存在，消费者是补证与复核。M 只交依据和判断对，不另定四态判法。

**判准作用域必须先固定**：当次指令能证明局部执行应遵循什么，不能自行证明产品设计满足用户需求。评模型局部遵循时，只用该次可得规则及明确适用的通用义务；评系统设计时另立系统范围的义务。来源名字不能代替权威性或适用性。

## ④ 不变内核：四态由两个问题推出

`K : {是,否,?}² → {pass, fail, not_applicable, undetermined}`：

| 条件 | 唯一结果 |
|---|---|
| A=否，B 任意 | not_applicable |
| A=是，B=是 | pass |
| A=是，B=否 | fail |
| 其余 | undetermined |

九种输入组合各有唯一落点。K 不看 trace 平台、执行者、业务名字或别轴结果。缺判准与缺事实不是两种违约状态，而是未定的原因。没有拿到材料不等于不适用；没有报错不等于满足。

**局部失败不等于根因归属**：复合范围上已确认的违反，只在该范围记一次；若证据仅支持“工具或数据源至少一方有问题”，不能推出双方各自 fail。各侧仍按各自证据判；定位缺口保留在原结论，供调查消费。

## ⑤ 汇总：反例成立容易，全称成立必须覆盖完整

`Agg : 有限逐项结果 × 范围覆盖依据 → 轴摘要与缺口`，按以下顺序：有已证 fail → 有偏差；否则有未定、待归类或范围未闭合 → 未定；否则至少一项 pass → 满足；否则全部有据不适用 → 不适用。空集只有在范围完整且确证没有适用义务时才是不适用，否则未定。

已有 fail 不因其他缺口消失，缺口也不因已有 fail 消失。复合范围的失败不能复制到候选责任轴。轴摘要只对声明范围有效；评测未运行或执行失败是运行状态，不冒充业务判断。

全链：`V = Agg({ K(M(q,T(x),y)) : q ∈ Q(T(x),y) }, 范围覆盖依据)`；T(x) 与 y 冻结后复用，最终交付评价消费结果，不回写判准或已发生事实。

## 承诺、分层与归位

| 承诺 | 数学约束 | 把关者（候选协议要求） |
|---|---|---|
| 不按执行者抢轴 | 类别取决于义务关系 | Q 的原子化与类别审核 |
| 结论必须有据 | 确定 A/B ⇒ 可核验依据 | M 的出处、版本及证据审核 |
| 值域穷尽互斥 | 九种输入恰有一出口 | K 决策表 |
| 缺口不被汇总抹掉 | 未闭合 ∧ 无 fail ⇒ 未定 | Agg 覆盖检查 |
| 未定位不伪造双错 | F₁∨F₂ 不推出 F₁∧F₂ | M 的主张范围审核 |

不变的是原子义务原则、K、Agg 和证据约束；可替换的是 T/Q/M 的 provider。更换 trace 改 T，增加业务义务改 Q，换取证与语义解释方式改 M。把“不可见判通过”翻译不成供料变化，属于被否决的判法例外。

| 现存机制 | 归位 |
|---|---|
| trace provider、案卷、实际输入重建 | ① T |
| 环节枚举、六轴义务模板、场景与项目声明 | ② Q 的素材及定义域；类别边界需重定 |
| 分析轴、证据读取、机器事实核对、语义评判、读取回执 | ③ M 的供料与约束 |
| 逐项五态、校验标注、轴级聚合 | ④/⑤ 当前承载处；尚未满足候选四态与对称证据要求 |
| Judge/fulfilled、按模型筛选的过程视图 | 结果消费者；后者为候选执行者视图 |

演化只保留两条：先用冻结判例检验职责边界；只有新增义务无法表达为现有关系时，才讨论修改类别集合。
