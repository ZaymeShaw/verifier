# 主轴「没证据判通过」重放实验（2026-10-17）

正式代码未改。脚本在本目录（`exp_main.py` 重放主轴、`samples.py` 取样本、`variant_*.py` 变体在进程内替换 `need_judge.run_need_judge`），结果 `out/`、汇总 `summary.txt`。

## 样本
- 目标：客户号 C92200000884 单轮 case，agno / langfuse 各一份过程轴报告（`rerun-20261017/*-r1`），各 3 次。
- 对照：实例用例池 32 条（批次 6dd73371，insurance-agno-e2e，自带 trace 与过程轴报告），各 1 次。无人工标注，变化逐条看原因。
- 只重放主轴（blocking 投影 + 交付判定），过程轴结论固定。模型 gemini-3.8-flash-medium。

## 结果

| 变体 | 目标（6 次） | 对照 F / NF / NE |
|---|---|---|
| 基线（现行代码） | F×6 | 24 / 6 / 2 |
| A：判 F 必须交 proof（引文程序核对） | F×5, NE×1 | 13 / 8 / 11 |
| B：只对业务数据对象的事实要 proof + 独立核对「引文能否推出结论」 | NE×6 | 4 / 8 / 20 |
| C：同 B，但核对方看整条调用记录（参数可绑定对象） | NE×6 | 9 / 7 / 16 |

## 看到的
1. 主轴单独重放，基线 6/6 判 F：同样的过程轴结论下主轴稳定地放行。10-16/17 整条流水线里主轴的摇摆主要随上游轴的结论变化。
2. A 无效：主轴拿搜索记录当 proof，引文确实在材料里，程序只能核引文存在，核不了「引文能否推出结论」；同时把 proof 套到格式、约束、建议类需求上，误伤对照。
3. B/C 能拦住目标，但对照大量变 NE。C 下仍为 NE 的主因（按理由文本粗分，约数）：
   - 业务工具多为自然语言检索（如 `policy_search(query="安锦宁名下的保单")`），返回记录不带被查对象的标识：8 条。严格按「证据能推出对象对应关系」都证明不了。
   - 证据没进主轴材料或没被记录：4 条（见第 4 点）。
   - 金额单位未注明、字段说明限制等：1–2 条。
   目标 case 与这 8 条在证据结构上是同一类（自然语言检索、返回不带被查标识）；区别只在目标 case 的工具返回自己写了「未提供 clientno，如需核实请使用 customer_detail」。
4. 独立发现：主轴材料预算（80000 字）把工具返回挡在外面，8/32 条有工具记录被排除；其中 ctl-45、52、53 的被排除返回在材料别处也没有，基线照样判 F。

## 待决（需要用户定，不是实验能定的）
- 「自然语言检索返回一批记录、返回里不带被查对象标识」算不算证明交付正确？
  算 → 目标 case 也得算（除非单独看工具自己的「需核实」提示）；不算 → 这个业务系统大部分查询类 case 都变 NE。
- 主轴材料预算挡掉工具返回时，主轴应怎么处理（判缺证 / 扩预算 / 让主轴能补查）。
