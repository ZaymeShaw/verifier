## 4. 发现

1. **按"模型看到的原样"核对，能消掉大部分误拒**，且不放过真错误（§2）。
2. **去重占位与引用冲突**：被换成"〔同 X〕"的那段，按现在给模型的规则 8 只能引 X，可 X 是另一条记录，角色不同。去重是上游展示层的事：由调用方算"看到过"时还原（§1），资源层不管；还原后 28 条全过、角色按被引的这一块。
3. **深层值没展开**：约 5%（92 / 1902）读回的记录里，嵌得深的值仍是 `content#N` 这种内部编号，模型看不到原文；而且编号每次建案卷可能不同。
4. **同一条记录有两种渲染**：过程轴读的本轴材料里字段写成 `{ref, status, value}`，`case.trace`（`record_body`）写成 `{status, value, chars}`。资源化时应只有一份规范文本。
5. **宽容规则确实三套不一致**：现过程轴核对把弯引号当直引号，`axis_loop/text.py` 不当。P1 统一为"`text.py` 的规则 + 说法轴的引号归一"（spec 修订记在 `spec/implementation/resources.md`）。
6. **"只能对上一处"太严，而且不是资源层该判的**：直接上线会让原来没拒的 806 条里 247 条被拒；抽查看，真正有问题的是"几处分属不同端 / 不同调用"，同一个值重复没问题。按 MCP，能单独读、单独引的最小单位是一个资源地址：资源层只管"在这个资源里找到没有"，要分清哪一端就引更细的资源（字段级模板资源 `…/observations/14/fields/output`），够不够由使用方判。`#` 块内位置不是 MCP 资源（按 MCP 读到的仍是整条记录），已去掉。
