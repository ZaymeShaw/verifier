# Math Abstract Skill

## 职责

把一个业务问题或系统的判定/处理逻辑提炼为数学骨架：什么是不变的内核，什么是可替换的映射。产出一份抽象层协议文档，不产出实现代码，不发明系统里不存在的管线。

范例：`spec/math-abstract/judge.md`。只学它的方法，不搬它的内容——那份文档里的符号与业务语义属于它自己的领域。

## 方法（五步）

1. **找内核签名。** 系统收敛到哪个核心判定/变换？写出签名：定义域 → 值域。值域必须封闭且穷尽——任何案子都有唯一落点，没有漏格。
2. **实参无出身。** 内核不关心实参怎么来的。所有"这个值从哪来 / 谁担保 / 多新鲜"的差异，压进实参的类型与元数据戳记，不进入内核逻辑。内核想偷看旁路输入，在类型上就办不到。
3. **变/不变分层定理 + 翻译规则。** 声明哪部分全局唯一（内核），哪部分因场景而异（映射的 provider）。给出翻译规则：任何"这里判法不一样"的诉求，必须先翻译成"这里的映射/物料不一样"；翻译不出来的是协议变更，走评审，不走接入。
4. **既有机制归位。** 把现存的每个机制归到唯一位置。判别式：供出一个值的是 provider；限定哪些值合法的是定义域声明；直接下内核结论的是在冒充内核——不许。
5. **短，且每个符号有消费者。** 每引入一个记号，必须指得出谁消费它、怎么消费。没有消费者的符号删掉。

## 产出合同（七节）

1. **不变式内核**：内核签名 + 关键性质（通常是"不关心实参出身"）。
2. **映射管线**：从原始现场到内核实参的映射复合，含时序约束（定格 / 先后 / 不回流）。
3. **链路图**：内核 + 管线的一图总览，ASCII 与 Mermaid 双形式，规则见下节。
4. **分层定理**：全局唯一 vs 场景各异，附翻译规则。
5. **归位表**：既有机制 → 唯一位置。缺仓库上下文时标注"未归位"，不编造。
6. **纪律的对偶面**：内核可以不关心出身，恰恰因为实参把出身带在身上；写清内核消费元数据的确定性规则（如缺料 → 诚实的不确定，不是自信的错误）。
7. **演化含义**：≤ 2 条方向性的话，不写实现计划。

## 链路图

每份抽象必附一节「链路图」：ASCII 文本图与 Mermaid flowchart 各一份，画的是同一张图——
原始输入经各映射到内核实参、内核到值域各落点的主管线；正文若有担保/旁证类偏关系，
画成侧链。密度学 `spec/math-abstract/judge.md` §3 的一页可读，符号用本抽象自己的。

- **符号取自本文**：图中每个节点、每条边都是本抽象内核/管线两节已定义的记号。
  图不引入正文没有的符号，也不遗漏正文管线的任何一步。
- **值域画穷尽**：内核出口按值域各落点画全，不省略分支。
- **侧链分明**：担保空间、偏关系等非主管线成分画成侧链（ASCII 用 ┆/┄，Mermaid 用
  `-.->`），不混入主数据流。
- **消费者门禁对图同样生效**：正文里没有消费者的符号不入图；图里的节点在正文找不到
  定义与消费者的，删图或补文，二选一。

骨架（记号仅示意占位，K/mᵢ/vᵢ 须换成本抽象定义的符号）：

```text
a ──m₁──→ m₁(a) ─┐
                 ├─ K ──→ v₁ / v₂ / …（值域各落点）
b ──m₂──→ m₂(b) ─┘
  ┆
  w（担保侧链，可选）
```

```mermaid
flowchart LR
  a -- "m₁" --> ma["m₁(a)"]
  b -- "m₂" --> mb["m₂(b)"]
  ma --> K{K}
  mb --> K
  K --> v1[落点 v₁]
  K --> v2[落点 v₂]
  z["担保空间（可选）"] -. w .-> mb
```

## 质量门禁

- **消费者存在性**：每个符号有明确消费者。
- **图文一致**：链路图与正文同源——无孤儿边、无仪式节点，ASCII 与 Mermaid 描绘同一张图。
- **穷尽性**：所有值域封闭穷尽，任何案子有唯一落点。
- **∀ 审计**：每条全称断言都有对应的检查者或结构保证；盖不了章的降级为局部断言。
- **构成性 vs 仪式性**：删掉某节后结论不变的，是仪式，删。
- **无实现细节**：不出现类名、接口设计、排期。
- **篇幅**：全文 ≤ 两页。

## 反模式

- **假数学**：用记号装点散文，符号之间没有可检查的关系。
- **过拟合符号**：把一次性的业务名词升格为记号。
- **盖章一切**：随手写 ∀ 而没有消费者/检查者。
- **硬依赖伪装**：内核附近直接摸具体物料，却声称是抽象。
- **声明当 provider**：把"限定哪些值合法"的定义域声明错归为供值方。

## 边界

- 不实现：只产协议骨架文档。
- 不发明管线：抽象必须来自系统里真实存在的机制，缺上下文就标注，不编造。
- 符号非代码：记号服务于论证，不是接口设计。
- 业务协议优先：与既有业务协议冲突时以协议为准，回来修抽象。
