# ToolLoop 最小试验台

这不是发布平台。普通 Python 构造函数定义 Harness，页面负责输入任务、运行和观察。
循环、工具调用、核心完成条件仍使用 `impl.core.tool_loop`；试验台不另写循环引擎。

## 直接体验（不用 Key）

```bash
python -m impl.tool_loop_lab --port 8030
```

打开 `http://127.0.0.1:8030/`，默认是 **脚本演示**。选择“提交与结束检查”，点击运行：

1. 脚本模型尝试直接结束，RequireDone 返回 Continue。
2. 提交引用了未读材料，DependsOn 返回 Deny。
3. 读取材料后尝试无效提交，submit 返回 accepted=false。
4. 修正提交，核心 hook 允许结束，end 返回有效提交参数。

脚本模式的模型回复是固定的，不理解输入，不代表真实模型效果。工具、hooks 和循环是真的。
真实模型可能走不同路径，不保证重现脚本中的拒绝次序。

第三个示例 **“聚类 → 可视化结果页”** 使用 8 条合成案例，调用 `read_reasons` / `read_case` / `submit_clustering`。
提交时每个类别的 `members` 必须包含 `{ref, evidence}`：reason 编号及支持这次入类的连续原文短句。
工具在原有覆盖、引用和结构检查之外，校验摘录非空且确实来自该条 reason；缺失、改写或引用其他 reason 的句子均拒绝提交，仍由同一模型按错误修正。
Prompt 要求共同说明适用于每个成员、相邻类边界一致、不同情况可单列、不把现象升级为确定根因。

聚类示例还挂载 `OverlapGuard`（`post_tool`）：只在 `submit_clustering` 的结构、引用、摘录及覆盖检查通过后，比较**同轴同标签**的各对聚类。
- 重叠率为 **交集成员数 / 较小类成员数**，不是交集除以并集。完全包含的小类也计为 100%。
- `build_clustering()` 显式设置 `OverlapGuard(threshold=0.5)`；**严格超过 50%** 拒绝，等于阈值放行。该值是可调整的实验目录约束，尚未验证为合理的语义质量阈值，不是数据推导的结论。
- 一次反馈列出全部超限的轴、标签、两类名称、规模、重叠率和共享 ref。Hook 只把返回改为 `accepted=false`，不删除成员、不自动合并，也不要求一条 reason 只归一类或强制证据片段互异。
- 规则提前写入模型实际收到的 prompt；后续仍由同一模型修正。不得为过关丢弃真实情况或合并无关现象，无法兼顾时应说明冲突。高重叠可以来自真实独立情况，因此拒绝**不证明语义重复**，通过也不证明聚类正确。
- 时间线区分“工具校验通过”和“Hook 拒绝提交”，详细数据保留具体重叠对。旧运行的冻结产物不被重新判定或改写。

没有新增模型、审查 agent 或独立流程；仅在已有提交后增加这个 Hook。全部检查通过后，核心完成 hook 才允许结束；`end` 单向转换为共享展示目录并附上逐成员证据，不改变源评测聚类协议。
面板在完整 reason 上方展示“入类依据”。出处校验不证明语义相关性，也不证明聚类正确；没有摘录的已有结果不会被自动补写依据。

运行后直接显示「轴 → 标签 → 语义聚类」目录、原始 reason 和案例输入输出，也可点“新窗口查看结果”。
渲染器固定复用 `AxesExperiment`，模型不生成 HTML；因此内容变化和排版变化可以分开测试。
普通 JSON 与执行时间线仍保留。结果页面绑定运行编号，查看或刷新不会重新调用模型；新试验覆盖旧记录后，旧页面明确显示已被替换。
脚本模式中的 5 类是预置演示，不作为真实模型的参考答案。真实模型模式自主分类，类数与次序不固定。

试验台也挂在 verifier 服务的 `/frontend/tool_loop_lab.html`；独立端口不需要重启评测服务。

## 单向对齐以前的真实 case

在聚类示例左侧填写源实例（例如 `http://127.0.0.1:8021`）与项目，点击 **“对齐 / 更新案例快照”**。

- 试验台只调用源侧已有的三个查询接口：`/api/run_workspace`、`/api/eval_axes/types`、`/api/axes_clustering/state`。不新增源接口，不共享存储，不回写标准或判定。
- 复制当前全部候选区的 case 身份、实际输入输出、轴 reason，以及可用的源聚类。未运行或无 reason 的 case 仍在对齐预览中明确显示，但不会伪造聚类材料。
- 候选区位置和 request_key 一起绑定；重名 case 不合并。源聚类只覆盖部分 case 时，会保留它原本的范围。
- 源批次运行中或对齐期间数据变化时拒绝保存，不把混合版本当成同一份样本。
- 点击“查看对齐的 case 与原聚类”先核对材料，不需要模型 Key；“使用源聚类标准”会把当时的标准填入任务输入。
- 聚类材料选择“已手动对齐的真实案例”，配置独立模型后运行。真实 case 禁止使用预置脚本冒充聚类。
- 源聚类**不进入实验模型的 prompt 或读取工具**，只在最终产物里用于人工对照。
- 运行后点击 **“按 case 对照源结果”** 查看同一 case 的源分类与实验分类；不同标准的对照会提示，不计算伪造的优劣分数。
- 后续源数据更新，手动再点一次“对齐”才换快照。对齐期间不调用 LLM，也不改已有实验结果绑定的旧材料。
- 每次运行带上快照 ID，拒绝从旧页面启动到另一份新快照。只保留最新对齐快照和最新试验，旧预览链接失效时明确提示。

这是试验台的单向适配，不是两套框架合并。完整 Trace 会随现有源查询接口经过内存，但不会复制保存到试验快照中。

## 独立供应商与 Key

```bash
cp .env.tool_loop.example .env.tool_loop
```

也可以直接在试验台的 **“独立模型连接”** 表单填写供应商地址、模型 ID、API Key，点击“保存模型配置”。
页面与手工编辑使用同一份仓库根目录 `.env.tool_loop`，不会写公共 `.env`。

- Key 首次填写，后续留空保留；换供应商地址必须重填，避免把原 Key 发往新地址。
- 可选参数 `temperature`（`TOOL_LOOP_TEMPERATURE`）用于探活和正式请求，不按模型名猜值。供应商若要求只能为 1，填写 1；修改后不继承旧 temperature 的连接冷却状态。
- 保存后密码框清空，GET 接口只返回 Key 是否已配置；不把 Key 放进浏览器存储。
- 文件通过原子替换写入，权限为 0600；配置版本冲突时拒绝覆盖，要求读取最新配置。
- 保存只校验格式，不发送模型请求、不验证供应商连通性。下次运行创建客户端时使用新配置，正在运行的客户端不变。
- 文件已 gitignore；同名进程环境变量优先。若启动时设置了 `TOOL_LOOP_*`，页面明确只读，不假装保存覆盖生效。
- 手工编辑后点“读取当前配置”即可，不必重启。

- 第一版支持 OpenAI-compatible Chat Completions + tool calls 协议；不是所有供应商原生协议都可直接接入。
- 必须是供应商真正支持工具调用和流式返回的模型。
- `TOOL_LOOP_REASONING_EFFORT` 默认留空，不向不支持的供应商强塞参数。
- 与公共 `.env`、评测模型、公共 fallback 无关；不经 tracing relay。单请求仍复用公共 LlmClient，保留既有本地上下文审计。
- Key 不传给页面或模型上下文。网络异常中的 Key 会在写入试验结果前脱敏。
- 开启真实模型模式再点击运行会产生费用；读取配置和刷新页面不会发起模型请求。
- 运行沿用 LlmClient 的短生成探活与端点冷却。探活失败时显示脱敏后的 HTTP/供应商错误及剩余冷却时间；探活等待超时与正式请求超时分别说明。冷却期间保留原因，但不会因读取状态重新请求供应商。旧版本吞掉的错误无法从历史结果恢复。

## 改工具和 hooks

编辑 [`examples.py`](examples.py) 中的 `build_basic(client)` / `build_checked(client)`，或 [`clustering_example.py`](clustering_example.py) 中的 `build_clustering(client)`；刷新配置/再点运行会重新加载固定示例文件。
聚类材料在 `clustering_example.py` 的 `CASES` / `TYPES` 中；页面任务输入就是本次聚类标准。
这就是普通 Python，可直接返回一个 `ToolLoop`。工具逻辑、辅助 hooks、核心 completion_hook、end 都在构造函数里。
页面展示实际工具定义、核心完成条件和本次冻结的构造源码，不在网页里执行任意 Python。

只加载服务指定的可信示例文件；修改它们等同于修改服务代码，应由开发者审核。HTTP 不接受模块路径、代码上传或任意文件读取。
每次加载/构造是独立实例；提交工具负责结构检查，核心 hook 负责有效提交是否存在，end 负责提取结果。

## 运行与数据边界

- 每实例同时只运行一个试验；并发重复提交会被拒绝。
- 只保留本试验台最新运行和事件，不清理正式评测数据。
- 数据：`data_root()/tool_loop_lab.sqlite3`。独立启动未设置实例 ID 时位于 `impl/data/tool_loop_lab.sqlite3`；挂在 verifier 时使用该实例的数据目录。
- SQLite 自动回收旧事件释放的空间，刷新后结果和运行状态都可恢复；服务中断后不自动重跑。
- 核心工具预算仍由原 ToolLoop 执行。另有 1200 秒协作式运行时限，在模型请求前后、工具边界及结束检查时生效。
- 停止是协作式，不会立刻杀掉正在阻塞的供应商请求或自定义工具；单请求默认超时 300 秒。
- 页面“模型请求次数”指 loop 步数。供应商请求内部的网络重试由 LlmClient 负责，不能把步数当作所有 HTTP 尝试次数。

## 文件职责

- `examples.py`：基础示例构造函数及不花费用的脚本模型。
- `clustering_example.py`：聚类 ToolLoop、合成材料、结构化前端产物与独立的脚本演示。
- `connection.py`：独立连接配置，复用现有 LlmClient。
- `alignment.py`：只读源 API 的单向投影与一致性检查；仅写试验台快照。
- `observation.py`：观察客户端/工具/hooks，保留原返回决定。
- `service.py`：构造并启动一次运行。
- `store.py`：最新运行和事件持久化。
- `api.py`、`__main__.py`：HTTP 与独立启动入口。
